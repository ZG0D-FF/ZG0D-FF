3.1 SQL Architecture & History

Originally developed by IBM at the San Jose Research Laboratory as Sequel for the System R project, SQL (Structured Query Language) is the standardized declarative language for managing relational databases.

The Functional Sublanguages of SQL

DDL (Data Definition) Commands (CREATE, ALTER, DROP) that define relation schemas, integrity constraints, and physical storage indices.
DML (Data Manipulation) Declarative commands (SELECT, INSERT, UPDATE, DELETE) for retrieving and modifying data tuples.
TCL (Transaction Control) Commands (COMMIT, ROLLBACK, SAVEPOINT) defining transaction boundaries and atomicity.
DCL (Data Control) Commands (GRANT, REVOKE) defining security policies and user privilege assignments.

Creating Tables with Integrity Constraints

CREATE TABLE department (
    dept_name VARCHAR(20) PRIMARY KEY,
    building VARCHAR(15),
    budget NUMERIC(12,2) CHECK (budget > 0)
);

CREATE TABLE instructor (
    ID CHAR(5) PRIMARY KEY,
    name VARCHAR(20) NOT NULL,
    dept_name VARCHAR(20),
    salary NUMERIC(8,2),
    FOREIGN KEY (dept_name) REFERENCES department(dept_name)
);
DDL Table Lifecycle Commands:
  • DROP TABLE r; completely removes the table schema and all its rows from the database catalog.
  • DELETE FROM r; retains the table schema and columns, but deletes all stored data rows.
  • ALTER TABLE r ADD column_name datatype; appends a new column (populated initially with NULLs) to an existing table.
  • ALTER TABLE r DROP COLUMN column_name; drops an existing column and its data.

3.3 The Three-Clause Query Structure

The fundamental building block of SQL retrieval consists of three declarative clauses: 

SELECT A1, A2, ..., An
FROM r1, r2, ..., rm
WHERE P;

Conceptual Execution Order of an SQL Query

1. FROM Clause Computes the Cartesian product of all relations listed: r1 × r2 × ... × rm.
2. WHERE Clause Applies the Boolean predicate P to filter surviving row combinations.
3. SELECT Clause Projects the requested attribute columns A1, A2, ..., An and computes expressions.
Duplicates in SQL: Unlike pure relational algebra (which operates strictly on mathematical sets and removes duplicates automatically), SQL relations are multisets (bags). The SELECT clause retains duplicate tuples unless explicitly commanded via SELECT DISTINCT.

3.4 Multi-Relation Queries & Joins

When multiple tables appear in the FROM clause, SQL forms the Cartesian product before filtering with the join predicate. 

-- Find names of all instructors along with course ID they teach
SELECT name, course_id
FROM instructor, teaches
WHERE instructor.ID = teaches.ID;

Natural Join vs. Explicit Join

A natural join automatically equates all columns with matching names in both tables and eliminates duplicate attribute columns: 

SELECT name, course_id
FROM instructor NATURAL JOIN teaches;
The Danger of NATURAL JOIN: If two tables happen to share an attribute name with different semantic meanings (e.g., student.dept_name and course.dept_name), a natural join will inadvertently require both to match, silently eliminating legitimate records! Use JOIN ... USING (attribute) or explicit ON predicates instead.

3.5 Set Operations: UNION, INTERSECT & EXCEPT

SQL supports mathematical set operations across two relations. Both input queries must be union compatible: they must possess the same number of columns, and corresponding column types must be compatible.

  • UNION: Computes the set union, automatically eliminating duplicates (use UNION ALL to retain duplicates).
  • INTERSECT: Computes the set intersection of rows appearing in both query results (use INTERSECT ALL for multisets).
  • EXCEPT: Computes the set difference (tuples in query 1 not present in query 2).

3.6 NULL Values & Three-Valued Logic

In SQL, NULL represents a missing, unrecorded, or inapplicable attribute value. Comparisons involving NULL return the truth value UNKNOWN rather than TRUE or FALSE.

Filtering Behavior: A WHERE clause keeps a row only if the predicate evaluates strictly to TRUE. Any tuple where the condition evaluates to FALSE or UNKNOWN is discarded.

3.7 Aggregation, GROUP BY & HAVING

SQL aggregate functions (AVG, MIN, MAX, SUM, COUNT) compute a single summary scalar over a collection of values. 

-- Find average instructor salary per department for departments with avg > 60000
SELECT dept_name, AVG(salary) AS avg_salary
FROM instructor
GROUP BY dept_name
HAVING AVG(salary) > 60000;
The Difference Between WHERE and HAVING:
  • WHERE filters individual tuples before grouping occurs.
  • HAVING filters entire groups after grouping and aggregate computation have occurred.

3.8 Nested Subqueries: IN, ALL, EXISTS & UNIQUE

A nested subquery is a SELECT-FROM-WHERE expression embedded inside another query.

  • Set Membership (IN / NOT IN): Tests if a value exists within the subquery's result set.
  • Set Comparison (> SOME / > ALL): Compares a scalar against every value in a set (e.g., > ALL tests if the scalar is strictly greater than the maximum value of the subquery).
  • Empty Set Test (EXISTS / NOT EXISTS): Returns TRUE if the nested subquery produces at least one row. Often used in correlated subqueries.

3.9 Database Modification: INSERT, UPDATE & DELETE

Data Manipulation Language (DML) statements alter the database state:

  • INSERT INTO table VALUES (...); or INSERT INTO table SELECT ...;
  • DELETE FROM table WHERE predicate; deletes rows satisfying the predicate.
  • UPDATE table SET column = expr WHERE predicate; modifies attribute values in surviving rows.

3.10 Worked Practice Exercises & Solutions

Exercise 3.1 — University SQL Queries (a, b, c)
Silberschatz Ch 3.1

(a) Find titles of courses in Comp. Sci. with 3 credits:

SELECT title
FROM course
WHERE dept_name = 'Comp. Sci.' AND credits = 3;

(b) Find IDs of all students taught by instructor Einstein (no duplicates):

SELECT DISTINCT takes.ID
FROM takes, teaches, instructor
WHERE takes.course_id = teaches.course_id
  AND takes.sec_id = teaches.sec_id
  AND takes.semester = teaches.semester
  AND takes.year = teaches.year
  AND teaches.ID = instructor.ID
  AND instructor.name = 'Einstein';

(c) Find highest salary of any instructor:

SELECT MAX(salary)
FROM instructor;
Exercise 3.2 — Grade Points & GPA Calculation
Silberschatz Ch 3.2

Question:

Compute total grade points earned by student '12345' across all completed courses, multiplying course credits by letter-grade value (A=4, B=3, C=2, D=1, F=0).

Lucid Solution:

SELECT SUM(course.credits * point_mapping.points) AS total_points
FROM takes
JOIN course ON takes.course_id = course.course_id
JOIN (
    VALUES ('A', 4), ('B', 3), ('C', 2), ('D', 1), ('F', 0)
) AS point_mapping(grade, points) ON takes.grade = point_mapping.grade
WHERE takes.ID = '12345';
Exercise 3.3 — Salary Raises for Instructors
Silberschatz Ch 3.3

Question:

Give a 5% salary raise to instructors earning less than $100,000, and a 3% raise to all others.

Lucid Solution:

UPDATE instructor
SET salary = CASE
    WHEN salary < 100000 THEN salary * 1.05
    ELSE salary * 1.03
END;
Order Dependency Warning: If coded as two independent UPDATE statements without a CASE construct, an instructor earning $98,000 might be raised to $102,900 by the first statement, and then mistakenly raised a second time by the subsequent statement! The CASE expression prevents this anomaly.
