Views, Filters & Insights

Practical GitHub Project Management • Understanding-first course notes

What this lesson is actually teaching

The main idea is that a GitHub Project can contain different views of the same project information, each designed for a different need.

Customize view → Sort → Filter → Save as view → Analyze with Insights

You do not need to keep one single arrangement of your project information. You can create multiple useful views and charts that present the same information in different ways.

1. Why create multiple views?

As a project grows, the amount of information in the issue list can become difficult to work with. Different people or tasks may require different ways of looking at the same information.

  • One view might show the basic project list without sorting or filtering.
  • Another might be sorted by due date.
  • Another might show only work assigned to a particular person.
  • Another might hide completed work.
  • Another might combine several conditions.

The important mental model is that views are different presentations of the same project information.

2. How changes to a view are indicated

When you modify an existing view, GitHub indicates that the view has unsaved modifications with a blue dot next to the table view.

This tells you that the current arrangement has changed from the saved version.

Think of the blue dot as:

“This view has been modified and the changes have not yet been saved.”

From there, you can save the modifications to the current view or save the modifications as a new view.

3. Customizing the fields in a view

Fields determine which pieces of project information are displayed in the view.

You can add fields and change their position by clicking and dragging them.

AddAdd a field useful for the current view.
MoveDrag fields into a different position.
ResizeAdjust field widths.
OrganizeArrange fields so the view is easier to read.

For example, the instructor adds the start field and moves it next to the do field. The instructor also changes field widths, giving the label more room.

4. Views become more useful as the project grows

As more issues are added to a project, the issue list becomes longer.

More issues → More information → More organization needed → More useful views

The instructor demonstrates that additional issues may require changes to sprint assignments and dates. The view can therefore be customized around the current needs of the project.

5. Creating a basic starting view

The instructor creates a basic view with no sorting, no filtering, and the fields needed for the project.

Key idea:

A view does not have to be heavily customized. A simple unsorted, unfiltered view can be useful as the general starting point.

6. Sorting a view

Once you have a basic view, you can create another version that organizes the same information differently.

AssigneesOrganize items according to who they are assigned to.
StatusOrganize items according to their status.
Due dateOrganize items according to when they are due.

Sorting changes the order → Filtering changes which items are shown

7. Saving a sorted view as a new view

Instead of replacing the original general-purpose view, the instructor saves the modified version as a new view.

General project view
        │
        ├── Unsorted / unfiltered
        │
        └── New view
              │
              └── Sorted by due date

The new view can be renamed and views can be rearranged by dragging them into different positions. The instructor names the new view “by due date”.

8. What is filtering?

Sorting controls the order of items. Filtering controls which items appear in the view.

Remember the difference:

Sort: “How should the items be ordered?”

Filter: “Which items should I see?”

9. Filtering by assignee

The instructor demonstrates filtering by an assignee.

assignee

GitHub provides suggestions as you type. The instructor then selects Jojo.

assignee → choose Jojo → show Jojo's items

10. Filtering by status

The instructor demonstrates another filter based on status.

status

The instructor selects done and demonstrates how adding a minus sign can negate the filter.

-status:done

status = done → negate it → items that are not done

Important concept:

The minus sign is used to negate a filter condition in the example demonstrated by the instructor.

11. Positive and negative filters

Filters can be expressed in both positive and negative ways.

status:todo

A negative filter excludes something:

-status:done

The instructor also demonstrates combining conditions using commas.

status:todo,status:in progress

When a value contains a space, such as in progress, the filtering system displays the value with quotation marks.

"in progress"

12. Combining multiple filters

The most useful views can combine several conditions.

  • An assignee filter for Jojo.
  • A due-date sort.
  • A status condition that excludes completed work.
Assigned to Jojo
        +
Not done
        +
Sorted by due date
        ↓
Jojo's active tasks organized by due date

This produces a focused working view for a particular person.

13. Saving a personalized task view

After creating the combined filter, the instructor saves the view as “Jojo's tasks”.

Configure → Filter → Sort → Save → Reuse

14. Filters can be used across different views

The same type of filtering can be applied to different project views. Each view can present a different combination of fields, sorting, filtering, and project information.

15. Filtering options

The instructor points out that GitHub provides many filtering options and refers learners to the filtering documentation for the complete set.

AssigneeFilter according to who an item is assigned to.
LabelsFilter according to labels.
FieldsUse project fields as filtering conditions.
ReviewersFilter using reviewers when applicable.
MilestonesFilter according to milestones.
Combined filtersCombine multiple conditions.

The transcript specifically demonstrates combining filters and negating filters.

16. Every view gets a URL

Specific project views receive their own URLs. This makes a saved view easy to share with other people.

Saved view → URL → Share with team

17. What are Insights?

Projects includes a visualization feature called Insights.

By default, the Insights area displays a visualization of the status of items in the project. The chart is customizable, so the default chart is only a starting point.

Project data → Insights → Chart → Customize visualization

18. Customizing an Insights chart

Chart typeChange how information is visually represented.
GroupingGroup information by a selected project property.
AxisModify the information represented on an axis where applicable.
FiltersLimit the information included in the visualization.

19. Chart types

The instructor demonstrates different chart types, including:

  • Stacked area chart
  • Bar chart

The chart type changes how the same project information is visually presented.

20. Grouping Insights data

The chart can group project information by different properties. The instructor demonstrates grouping by assignee.

Project items
      ↓
Group by assignee

Visualize the items for each assignee

Depending on the selected configuration, additional chart settings such as the other axis can also be modified.

21. Saving and renaming charts

After configuring an Insights visualization, you can save it as a new chart or modify an existing chart.

The instructor also demonstrates renaming the chart so its purpose is immediately understandable.

Practical idea:

Name charts according to the question they help answer. This makes a collection of Insights charts easier to understand later.

22. Sharing Insights

Like project views, Insights charts have URLs. A configured chart can therefore be shared with team members by giving them its specific link.

The instructor also mentions that screenshots can be used when the visualization needs to be included in project-related material.

Configure chart → Save → URL → Share with team

23. Managing an Insights chart

Charts can be managed from the Insights interface.

  • Duplicate a chart.
  • Delete a chart.
  • Configure a chart.
  • Modify the existing chart.

This makes it possible to create variations without necessarily rebuilding everything from the beginning.

24. Historical charts

The instructor also mentions a feature called historical charts.

25. Views vs. Insights

ViewsChange how project items are displayed, ordered, and filtered.
FiltersControl which project items are included in a view.
SortingControls the order of items in a view.
InsightsTurn project information into configurable visualizations.

Views = organize project information

Filters = narrow project information

Sorting = order project information

Insights = visualize project information

28. One-minute understanding check

Q: Why create multiple views?

A: Different project needs may require different arrangements, sorting, or filtering of the same project information.

Q: What does the blue dot indicate?

A: It indicates that the view has been modified.

Q: What is the difference between sorting and filtering?

A: Sorting changes the order of items; filtering controls which items are shown.

Q: How can you create a personalized view for one person?

A: Filter by the assignee and save the resulting configuration as a separate view.

Q: How can you exclude completed items?

A: The lesson demonstrates selecting the done status and using a negative/minus filter to exclude it.

Q: Can filters be combined?

A: Yes. The lesson demonstrates combining filtering conditions and using commas.

Q: What is Insights used for?

A: Insights provides visualizations of project information and allows the charts to be customized.

Q: Can Insights charts be customized?

A: Yes. The lesson demonstrates changing chart type, grouping, axes, and filters.

Q: Can views and charts be shared?

A: Yes. The instructor explains that both views and Insights charts have URLs that can be shared.

29. The core mental model

If you remember only one thing from this lesson, remember this:

One project
     │
     ├── View 1 → General project information
     ├── View 2 → Sorted by due date
     ├── View 3 → One person's active tasks
     └── View 4 → Another custom project perspective

     +

     Insights
       │
       ├── Charts
       ├── Groups
       ├── Filters
       └── Visual analysis

The project data stays connected, while the views and Insights configurations provide different ways of working with and understanding that information.
