PRACTICAL GITHUB ACTIONS

Entry Point + action.yml

Understanding-first notes from the two supplied course transcripts, cross-checked against the course repository.

What are we building?

The previous lesson created the generator Dockerfile. These two lessons add the two files that make that Docker-based GitHub Action actually usable:

Dockerfile ↓ calls entrypoint.sh ↓ runs Python → /usr/bin/feed.py ↓ generates podcast.xml ↓ git add → git commit → git push action.yml ↓ tells GitHub Actions use Dockerfile + inputs + branding ↓ runs entrypoint.sh

Big picture: action.yml describes the Action to GitHub. Dockerfile describes the execution environment. entrypoint.sh contains the commands that execute inside that environment.

1. Creating the entry point

What is entrypoint.sh?

It is a shell script containing the terminal commands that should run when the Docker-based Action starts.

Think of it as the Action's command sequence: configure Git → run Python → commit the generated file → push it back.

Complete lesson-aligned entry point

#!/bin/bash

echo "--------------------------------"
echo "Running Podcast Generator"
echo "--------------------------------"

git config --global user.name "$GITHUB_ACTOR"
git config --global user.email "$INPUT_EMAIL"

git config --global --add safe.directory /github/workspace

python3 /usr/bin/feed.py

git add -A
git commit -m "Update feed"
git push --set-upstream origin main
Transcript wording vs code: the transcript explains the commands verbally. The code above expresses those commands in a valid shell-script form. In particular, /github/workspace is the GitHub Actions workspace path used by the safe-directory command.

2. Read the entry point line by line

CodeWhat it doesWhy it matters
#!/bin/bashShebang. Selects Bash as the interpreter.Tells the system how to execute the script.
echo "..."Prints a message to the action log.Creates visible sections and helps debugging.

git config --global user.email "$INPUT_EMAIL"Sets the Git commit email from the Action input.Connects the commit identity to the Action's input configuration.

git commit -m "Update feed"Creates a Git commit.Records the generated feed change.
git push --set-upstream origin mainPushes the commit to the remote main branch and sets its upstream.Sends the generated result back to GitHub.

3. The important variables

GITHUB_ACTOR

GitHub Actions context value representing the user or account that triggered the workflow.

INPUT_EMAIL

An Action input. The later action.yml file defines this input.

/github/workspace

The workspace location used by GitHub Actions for the checked-out repository.

Key connection: INPUT_EMAIL is not random. The shell script expects it, so action.yml must define an input named email. GitHub Actions exposes Action inputs to the container as INPUT_* environment variables.

4. Why python3 /usr/bin/feed.py?

The previous Dockerfile copied the generator into the image:

COPY feed.py /usr/bin/feed.py

Therefore the entry point must execute the same destination path:

python3 /usr/bin/feed.py

This is a classic Dockerfile → entrypoint connection:

COPY feed.py /usr/bin/feed.py ↓ file exists here ↓ python3 /usr/bin/feed.py ↓ generator runs

5. Creating action.yml

What is action.yml?

action.yml is the metadata/configuration file that tells GitHub what this Action is, what inputs it accepts, how it runs, and how it should appear when published.

Important: this file is YAML. A Dockerfile is not YAML. The two files use different syntaxes.

Lesson-aligned action.yml

name: Podcast Generator
author: Your Name
description: Generate podcast feeds from another repository

runs:
  using: docker
  image: Dockerfile

branding:
  icon: git-branch
  color: red

inputs:
  email:
    description: Email address used for Git commits
    required: true
    default: ${{ github.actor }}@localhost

  name:
    description: Name used for Git commits
    required: true
    default: ${{ github.actor }}
Important accuracy note: the transcript's spoken explanation of the exact YAML is abbreviated and contains some conversational wording. The code block above captures the intended structure and the variable relationships taught in the lesson. Replace Your Name with the actual author value used by the course.

6. Understand runs

runs:
  using: docker
  image: Dockerfile

This tells GitHub that the Action executes using Docker and that the Dockerfile in the Action repository defines the image/environment.

action.yml │ ├── metadata ├── inputs └── runs: Docker ↓ Dockerfile ↓ container environment ↓ entrypoint.sh ↓ feed.py

7. Understand branding

branding:
  icon: git-branch
  color: red

The transcript explains that Marketplace Actions can have an icon and color. The lesson chooses the git-branch Feather icon and red branding.

Branding affects how the Action is presented. It is not part of the generator's execution logic.

8. Understand Action inputs

inputs:
  email:
    description: Email address used for Git commits
    required: true
    default: ${{ github.actor }}@localhost

The Action declares an input called email. The entry point then reads the corresponding environment variable as INPUT_EMAIL.

action.yml email ↓ GitHub Actions input handling ↓ INPUT_EMAIL ↓ entrypoint.sh git config --global user.email "$INPUT_EMAIL"

9. What about the name input?

The transcript says the Action also gets the name and makes it required with a default based on the GitHub actor.

name:
  description: Name used for Git commits
  required: true
  default: ${{ github.actor }}

The important lesson is the relationship between Action inputs and the values consumed by the execution environment.

12. Exam / interview memory points

  • entrypoint.sh: shell script executed as the Docker Action's entry point.
  • Shebang: #!/bin/bash selects Bash as the interpreter.
  • GITHUB_ACTOR: identifies the GitHub actor associated with the run.
  • INPUT_EMAIL: environment variable corresponding to the Action input email.
  • safe.directory: marks the workspace as trusted for Git operations.
  • feed.py: Python generator executed from /usr/bin/feed.py.
  • git add -A: stages changes.
  • git commit: records changes in Git history.
  • git push: sends the commit to the remote repository.
  • action.yml: defines Action metadata, inputs, execution method, and optional Marketplace branding.
  • runs.using: docker: tells GitHub Actions to run the Action using Docker.
