What Exactly Are GitHub Actions?

GitHub Actions are GitHub's automation engine.

Instead of manually doing repetitive tasks every time something changes, GitHub can perform those tasks automatically.

Think of it like this

Real LifeGitHub
Motion sensor detects movementSomeone pushes code
Lights turn on automaticallyWorkflow starts automatically
No manual effortNo manual commands

Basic Formula

Event Happens
      ↓
GitHub Detects It
      ↓
Workflow Starts
      ↓
Steps Execute
      ↓
Job Finishes

This simple chain powers everything from testing software to deploying websites.

When Can GitHub Actions Run?

Two major ways appear immediately in this lesson.

1. Time-Based Automation

GitHub can run workflows on a schedule.

Every day at midnight
Every Monday
Every hour

This is useful for backups, reports, or cleaning repositories.

2. Event-Based Automation

Workflows can start when something happens.

Examples include:
  • Pushing a branch
  • Opening a Pull Request
  • Merging code
  • Publishing a release
Later in the course you'll create workflows triggered by these events.

Understanding YAML

The instructor chooses YAML because XML is difficult to write manually.

YAML Example

title: My Podcast
author: DJ
episode:
  title: Episode 1
  audio: intro.mp3

Equivalent XML

<podcast>
  <title>My Podcast</title>
  <author>DJ</author>
</podcast>

YAML is cleaner, easier to edit, and much more pleasant for humans.

The GitHub Action will later convert this simple YAML into a proper RSS XML file.

What Happens After Saving?

Many beginners think the website appears instantly. Actually, GitHub builds it first.

   ▼

Eventually you'll receive a public URL like:

That URL displays your README as a webpage.
