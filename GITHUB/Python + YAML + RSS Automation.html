Reading feed.yaml

The first real task is opening the YAML file. 
with open("feed.yaml") as file:
    yaml_data = yaml.safe_load(file)
### Step-by-Step #### Step 1 
with open(...)
Opens the file safely. #### Step 2 
as file
Creates a temporary file variable. #### Step 3 
yaml.safe_load(file)
Reads the YAML and converts it into a Python dictionary. Imagine this YAML: 
title: Hiking Treks
author: DJ
becoming this Python object: 
{
"title":"Hiking Treks",
"author":"DJ"
}
Now accessing values becomes easy. 
yaml_data["title"]
yaml_data["author"]
`safe_load()` is intentionally used instead of `load()` because it avoids executing unsafe YAML objects.

iTunes Tags Explained

You probably noticed strange names. 
itunes:author
itunes:image
itunes:duration
Why? Podcast RSS extends normal RSS. | Normal RSS | Podcast Extension | |-------------|------------------| | title | itunes:author | | description | itunes:image | | link | itunes:duration | Apple introduced these extensions long ago, and nearly every podcast platform still understands them.

The Enclosure Tag

This is arguably the most important podcast tag. Without it, podcast apps cannot locate the audio. RSS looks like:
Python: 
xml_tree.SubElement(
item_element,
"enclosure",
{
"url":link_prefix+item["file"],
"type":"audio/mpeg",
"length":item["length"]
}
)
### Why Hardcode `audio/mpeg`? Every file in this project is MP3. Since the type never changes, the instructor hardcodes it instead of storing it in YAML.

Common Debugging Mistakes

The instructor encounters another error. Cause? Missing quotation marks. Wrong: 
item[file]
Python thinks `file` is a variable. Correct: 
item["file"]
The same applies to: 
item["length"]
item["title"]
item["description"]
Always quote dictionary keys.
