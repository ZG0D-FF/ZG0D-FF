💡 Lucid Mechanical Insight: What is the AWS Free Tier Really?
Think of the AWS Free Tier like a hotel valet pass with a complimentary credit. AWS provides you access to their multi-billion dollar enterprise infrastructure, but segments it into three distinct buckets:
  1. 12 Months Free: Starts the exact day your account is verified. You get 750 compute hours/month of micro virtual servers (EC2) and 5 GB of storage (S3).

❓ Experiment 1 Viva Voce Solutions (Lucid & Verified)

Q1: What is AWS CloudShell and how does it differ from a local terminal?
Lucid Answer:
AWS CloudShell is a browser-based, fully-managed Linux shell environment pre-configured with the AWS CLI, Python, Git, and Docker. Unlike a local terminal on your desktop:
  • Zero Credential Storage: It automatically inherits your active browser session credentials via temporary container roles. You do not store access keys on your machine.
  • Pre-installed Tooling: No need to install Python, Boto3, or AWS CLI v2 locally. Everything is kept updated by AWS.
  • Cloud Storage: Provides 1 GB of persistent storage in the $HOME directory that stays saved between sessions within the same AWS region.
Q2: List any three services available in AWS Free Tier.
Lucid Answer:
Three prominent services include:
  1. Amazon EC2 (Elastic Compute Cloud): 750 hours per month of t2.micro (or t3.micro) compute instances for 12 months.
  2. Amazon S3 (Simple Storage Service): 5 GB of standard object storage, 20,000 GET requests, and 2,000 PUT requests per month for 12 months.
  3. AWS Lambda: 1,000,000 free function requests and up to 3.2 million seconds of compute time every month under the Always Free tier.
Q3: Why does AWS require a credit or debit card for the free tier?
Lucid Answer:
AWS requires payment card details for two critical reasons:
  1. Identity Verification & Fraud Prevention: It confirms that the registrant is a genuine individual and blocks automated spambots and cryptocurrency miners from spinning up thousands of fraudulent free accounts.
  2. Overage Billing Mechanism: The Free Tier has strict boundaries. If an account uses resources beyond the free tier limits (such as launching a high-memory 64-core server or keeping 100 GB in S3), AWS needs an established billing method to charge for the excess usage.
Note: AWS performs a temporary $1 authorization transaction that is voided immediately to verify card validity.
Q4: How do you list S3 buckets using AWS CLI?
Lucid Answer:
Run the standard high-level command: 
aws s3 ls
To inspect the objects inside a specific bucket named my-test-bucket, append the S3 URI: 
aws s3 ls s3://my-test-bucket/
Alternatively, using the lower-level API command: 
aws s3api list-buckets --query "Buckets[].Name" --output table
Q5: What precautions should be taken to avoid charges on the Free Tier?
Lucid Answer:
Follow these 5 ironclad industry rules:
  1. Stick strictly to t2.micro / t3.micro: Never launch other instance families (e.g., t2.medium, c5.large) as they are billed from the first second.
  2. Run at most 1 EC2 instance continuously: 750 hours covers exactly one single instance running 24/7 for a 31-day month ($24 \times 31 = 744\text{ hours}$). Running 2 instances uses 750 hours in 15 days!
  3. Release Unattached Elastic IPs: AWS allocates Elastic IPs for free while attached to a running instance, but charges ~$0.005/hour if the instance is stopped or the IP is unattached.
  4. Terminate Unused Resources: Stop or terminate EC2 instances and empty/delete S3 buckets when lab practice is complete.
  5. Activate Billing Alerts & Free Tier Notifications: Enable Receive Free Tier Usage Alerts in Account Preferences and set up an AWS CloudWatch $0.01 Billing Alarm.

💡 Lucid Mechanical Insight: What is an EC2 Instance Under the Hood?
In traditional data centers, provisioning a server meant purchasing a physical rack chassis, installing RAM and disks, connecting power, and plugging in Ethernet cables. This took weeks.

Amazon Elastic Compute Cloud (EC2) turns hardware into software. AWS maintains colossal multi-tenant server facilities running hypervisors (such as the AWS Nitro System). When you launch an EC2 instance:
  1. The hypervisor carves out exact virtual CPU (vCPU) and memory (RAM) slices on a physical host server.
  2. It clones an AMI onto a high-performance network drive called an EBS Volume (Elastic Block Store).
  3. It injects your chosen Public Key into the Linux ~/.ssh/authorized_keys file during initial boot.
  4. It attaches a Security Group filter that intercepts incoming packets before they ever touch the virtual operating system.

🏛️ The Five Core Architecture Pillars of EC2

Architecture Pillar Physical World Analogy AWS Technical Reality
1. AMI (Machine Image) A pre-cloned USB installation drive containing Windows or Linux. An encrypted snapshot of a bootable root volume containing OS, drivers, and pre-packaged utilities.
2. Instance Type (e.g. t2.micro) The CPU and RAM stickers on a laptop motherboard. A hardware configuration specification. t2.micro provides 1 vCPU and 1 GiB RAM with burstable CPU credit accumulation.
3. Key Pair (.pem) A physical lock on a front door. Amazon keeps the padlock; you hold the only physical key. Asymmetric cryptography: The public key is placed on the server; the private key (.pem) never leaves your custody.
4. Security Group A security guard standing outside the server room with a strict guest checklist. A stateful virtual firewall. If an inbound packet is allowed (e.g., SSH Port 22), the return outbound traffic is automatically allowed.
5. Public IP vs Elastic IP A temporary hotel room phone number vs a permanent dedicated phone line. A standard Public IPv4 address is dynamically released whenever the instance stops. An Elastic IP is a fixed, static IPv4 allocated to your AWS account.

❓ Experiment 2 Viva Voce Solutions (Lucid & Verified)

Q1: What is an Amazon Machine Image (AMI)?
Lucid Answer:
An Amazon Machine Image (AMI) is a master template that contains the software configuration (operating system, application server, and pre-installed packages) required to launch an instance. Think of it as a pre-packaged "gold master" snapshot of an entire hard drive. AWS provides official AMIs (Amazon Linux, Ubuntu, Red Hat, Windows Server), third-party AMIs via the AWS Marketplace, and allows users to create Custom AMIs from their own running instances.
Q2: What are the functions of a security group in EC2?
Lucid Answer:
A Security Group acts as a virtual firewall that controls incoming (inbound/ingress) and outgoing (outbound/egress) network traffic at the instance level. Core functions:
  • Default Deny Inbound: By default, all incoming traffic is blocked unless an explicit rule allows it (e.g. Port 22 for SSH, Port 80 for HTTP).
  • Default Allow Outbound: By default, all outgoing traffic from the instance to the internet is allowed.
  • Stateful Filtering: If an inbound request is permitted on port 22, the response packet is automatically allowed back out regardless of egress rules.
Q3: How does a key pair ensure secure EC2 login?
Lucid Answer:
EC2 uses asymmetric public-key cryptography instead of insecure passwords.
  1. When the instance launches, AWS places the Public Key inside the virtual machine at ~/.ssh/authorized_keys.
  2. You hold the corresponding Private Key (the .pem file) on your local computer.
  3. During SSH connection, the server challenges your client with an encrypted message that can only be decrypted by your private key. Because passwords are disabled, brute-force dictionary attacks are completely ineffective.
Q4: What is the difference between Amazon EC2 and Amazon Lightsail?
Lucid Answer:
Feature Amazon EC2 Amazon Lightsail
Target Audience Enterprise developers requiring custom architectures, auto-scaling, and fine-grained VPC control. Students, hobbyists, and small businesses needing simple web hosting (WordPress, basic node apps).
Pricing Model Granular per-second billing for compute, EBS storage, data transfer, and elastic IPs separately. Predictable, fixed all-inclusive monthly bundle (e.g. $3.50/month includes CPU, RAM, SSD, and data transfer).
Configuration Complexity High: Requires VPCs, subnets, route tables, and security groups. Low: 1-click simplified deployment with zero network setup required.
Q5: How do you stop or terminate an instance?
Lucid Answer:
Via AWS Console: Select instance → Click Instance State → Choose Stop Instance or Terminate Instance.

Via AWS CLI:

💡 Lucid Mechanical Insight: What is Object Storage vs. File Systems?
On your laptop (File Storage / NTFS / ext4), files live in a hierarchical tree of physical folders: C:\Users\John\Documents\report.pdf. If you change one sentence, the OS modifies specific disk sectors in-place.

Amazon S3 is Object Storage:
  • There are no physical directories! S3 is a completely flat key-value store. When you see photos/2026/vacation.jpg, the string photos/2026/vacation.jpg is simply the object's Key (name). The slashes are just characters in the name.
  • Objects are immutable: you do not modify 2 bytes in an S3 object. You upload a replacement object that overwrites the existing one.
  • Every bucket name is globally unique across all AWS accounts worldwide—like an internet domain name!

python — s3_script.py (Production Ready) 
import boto3
import uuid
from botocore.exceptions import ClientError

# Initialize low-level S3 client
s3_client = boto3.client('s3')

# S3 bucket names must be globally unique across all AWS accounts
unique_id = uuid.uuid4().hex[:8]
bucket_name = f"aws-lab-study-snaps-{unique_id}"
region = s3_client.meta.region_name or "us-east-1"

print(f"[1] Initiating bucket creation: {bucket_name} in {region}")

# CRITICAL AWS TRAP: us-east-1 does not accept LocationConstraint!
try:
    if region == "us-east-1":
        s3_client.create_bucket(Bucket=bucket_name)
    else:
        s3_client.create_bucket(
            Bucket=bucket_name,
            CreateBucketConfiguration={'LocationConstraint': region}
        )
    print(f"    ✓ Bucket created successfully!")
except ClientError as e:
    print(f"    ✗ Bucket creation failed: {e}")
    exit(1)

# [2] Upload local testfile.txt to S3 bucket
local_file = "testfile.txt"
s3_key = "uploaded_testfile.txt"

print(f"[2] Uploading '{local_file}' as '{s3_key}'...")
s3_client.upload_file(local_file, bucket_name, s3_key)
print("    ✓ Upload complete!")

# [3] List objects inside the newly created bucket
print(f"[3] Listing objects in s3://{bucket_name}/:")
response = s3_client.list_objects_v2(Bucket=bucket_name)
for obj in response.get('Contents', []):
    print(f"    • Key: {obj['Key']} | Size: {obj['Size']} bytes | StorageClass: {obj['StorageClass']}")

# [4] Delete the uploaded object (Prerequisite before deleting bucket)
print(f"[4] Deleting object '{s3_key}'...")
s3_client.delete_object(Bucket=bucket_name, Key=s3_key)
print("    ✓ Object deleted successfully!")

# [5] Delete the bucket
print(f"[5] Deleting S3 bucket '{bucket_name}'...")
s3_client.delete_bucket(Bucket=bucket_name)
print("    ✓ Bucket removed cleanly from AWS account!")

⚠️ Exam Trap: The "BucketNotEmpty" Error & us-east-1 Quirk
  1. BucketNotEmpty Error: If you execute s3.delete_bucket(Bucket=name) while even a single 1-byte file or incomplete multipart upload exists inside, AWS immediately throws ClientError: BucketNotEmpty. An S3 bucket must be 100% empty before it can be deleted!

❓ Experiment 3 Viva Voce Solutions (Lucid & Verified)

Q1: What is Amazon S3 and how does object storage differ from block storage (EBS)?
Lucid Answer:
Amazon S3 is an Internet-accessible Object Storage service designed for storing unstructured files (images, backups, videos, logs).
Key Differences:
  • Access Method: S3 is accessed via HTTP/HTTPS REST APIs from anywhere in the world. EBS (Elastic Block Store) is raw block storage that can only be mounted to a single EC2 instance via the internal hypervisor bus.
  • Data Mutability: EBS permits direct sector-level reads and in-place writes (essential for operating systems and relational databases like PostgreSQL). S3 stores complete immutable objects: any update replaces the entire file.
  • Scalability: S3 has practically infinite elastic capacity without pre-provisioning. EBS volumes must be pre-allocated (e.g. 50 GB) and paid for regardless of whether they are full.
Q2: What are the global naming rules for an Amazon S3 bucket?
Lucid Answer:
Because S3 bucket names form DNS-compliant hostnames (e.g., https://mybucket.s3.amazonaws.com), AWS strictly enforces:
  1. Must be globally unique across all AWS accounts worldwide.
  2. Length must be between 3 and 63 characters long.
  3. Can consist only of lowercase letters, numbers, and hyphens (-). No uppercase letters or underscores (_) allowed.
  4. Must begin and end with a letter or number (not a hyphen).
  5. Must not be formatted as an IPv4 address (e.g., 192.168.1.1).
Q3: What is Boto3 and what is the difference between client and resource?
Lucid Answer:
Boto3 is the official Python SDK for AWS.
It provides two levels of abstraction:
  • boto3.client('s3') (Low-Level): Provides a direct 1:1 mapping to the underlying AWS REST API. It returns raw Python dictionaries representing JSON responses. It has 100% service coverage and supports all newer AWS features immediately.
  • boto3.resource('s3') (High-Level): Provides an object-oriented Pythonic interface with classes like Bucket and Object (e.g. bucket.delete()). While cleaner to read, AWS has put resources into maintenance mode, so newer AWS services do not support resources. Production code standardizes on client.
Q4: What error occurs if you attempt to delete an S3 bucket that still contains objects?
Lucid Answer:
AWS will reject the request with HTTP Status Code 409 Conflict and throw: 
botocore.exceptions.ClientError: An error occurred (BucketNotEmpty) when calling the DeleteBucket operation: The bucket you tried to delete is not empty
To successfully delete the bucket, you must first delete all objects (and all versioned delete markers if versioning was enabled).
Q5: Why does create_bucket fail if LocationConstraint is improperly passed?
Lucid Answer:
When Amazon S3 launched in 2006, us-east-1 (N. Virginia) was the original and only region. As other regions were introduced (ap-south-1, eu-west-1), AWS required a LocationConstraint parameter to place the bucket outside the default region.

If you explicitly pass CreateBucketConfiguration={'LocationConstraint': 'us-east-1'}, the S3 endpoint rejects it with InvalidLocationConstraint because us-east-1 is the implicit default. Any other region requires the parameter.

Q1: What are the primary advantages of serverless computing?
Lucid Answer:
The five core pillars of serverless computing are:
  1. Zero Server Management: No operating systems to install, patch, or secure.
  2. Continuous Automatic Scaling: Scales automatically from 0 requests to thousands of concurrent requests without manual capacity planning.
  3. Pay-for-Value Billing: No cost when idle. You pay strictly for compute time consumed (measured in milliseconds).
  4. Built-in High Availability & Fault Tolerance: Automatically replicated across multiple Availability Zones in a region.
  5. Fast Time to Market: Developers focus entirely on core business logic rather than infrastructure plumbing.
Q2: How is an AWS Lambda function triggered?
Lucid Answer:
Lambda functions are invoked in three distinct interaction models:
  • Synchronous (Request-Response): The caller waits for Lambda to execute and return a response immediately (e.g. Amazon API Gateway, Application Load Balancer).
  • Asynchronous (Event): The caller sends the event and immediately receives an acknowledgment; Lambda queues and processes the event in the background with automatic 2-time retry logic (e.g. Amazon S3 object uploads, Amazon SNS notifications).
  • Poll-Based / Event Source Mapping: Lambda periodically polls an external streaming or queue service and processes batches of records (e.g. Amazon SQS, Amazon Kinesis, Amazon DynamoDB Streams).
Q3: What is the difference between event and context objects?
Lucid Answer:
Dimension The event Object The context Object
Origin Supplied by the external caller / triggering service. Supplied by the AWS Lambda runtime system.
Contents Input data payload (e.g. JSON request body, headers, S3 bucket names, query strings). Execution metadata (function name, ARN, remaining execution time, memory limit, request ID).
Mutability A standard Python dict that you can inspect, parse, and mutate. A Python object providing runtime inspection methods (e.g. get_remaining_time_in_millis()).
Q4: What permissions are required to use Lambda with other AWS services?
Lucid Answer:
Lambda requires two separate permission constructs:
  1. Lambda Execution Role (What Lambda can DO): An IAM Role assumed by the Lambda service (`lambda.amazonaws.com`) granting permissions to access other services, such as reading an S3 object (`s3:GetObject`) or writing to a DynamoDB table (`dynamodb:PutItem`).
  2. Resource-Based Policy (Who can INVOKE Lambda): A policy attached directly to the Lambda function granting external services (e.g. Amazon S3 or API Gateway) permission to trigger the function.
Q5: Can Lambda interact with S3 or DynamoDB? How?
Lucid Answer:
Yes, seamlessly:
  • With Amazon S3: Lambda can act as a trigger (S3 invokes Lambda whenever a file is uploaded to automatically resize images or parse CSVs) AND as an active client (Lambda uses Python's bundled boto3 to upload, download, or delete S3 files).
  • With Amazon DynamoDB: Lambda uses boto3.resource('dynamodb').Table('Users') to perform microsecond CRUD queries, OR triggers on DynamoDB Streams to process real-time database changes.

⚠️ Exam Trap: The Golden Rule of IAM Policy Evaluation
When evaluating whether a request is allowed or denied, the AWS IAM Policy Engine follows strict mathematical precedence:
  1. Default Deny (Implicit Deny): By default, all requests are denied.
  2. Explicit Allow: If an attached policy grants an "Effect": "Allow", access is permitted.
  3. Explicit Deny OVERRIDES Everything: If even a single attached policy (user, group, role, or SCP) contains an "Effect": "Deny" matching the action, the request is immediately rejected, overriding 100 other "Allow" statements!

Q2: What does an IAM policy JSON document contain?
Lucid Answer:
An IAM Policy is a JSON document containing a Statement array with 5 core keys:
  • Sid (Statement ID): An optional human-readable identifier for the statement.
  • Effect: Specifies whether the statement results in an Allow or an explicit Deny.
  • Principal: The entity allowed or denied access (used in resource policies and role trust policies).
  • Action: The specific AWS API calls covered (e.g. "s3:GetObject", "ec2:StartInstances").
  • Resource: The specific AWS resources identified by their ARN (e.g. "arn:aws:s3:::mybucket/*").
  • Condition: Optional constraints (e.g. require MFA, enforce TLS, or restrict to corporate IP CIDR).
Q3: Why should root user access be avoided for daily operational tasks?
Lucid Answer:
The root user is created with the email address used to register the account and possesses absolute, irrevocable administrative power across every service, billing setting, and resource. It cannot be restricted by IAM policies.

If a developer accidentally commits root access keys to a public GitHub repository, malicious attackers can take over the entire AWS infrastructure, deploy expensive crypto-mining clusters, and lock out the account owner. Best practice dictates creating specific IAM users/roles adhering to Least Privilege and locking the root account behind hardware MFA.
Q4: Can an IAM user belong to multiple groups?
Lucid Answer:
Yes. An IAM user can belong to up to 10 user groups (and up to 300 with quota increases). When a user belongs to multiple groups, their effective permissions are the union of all policies attached to those groups (subject to the overriding power of any explicit Deny).
Q5: How is access evaluated when an identity has multiple policies?
Lucid Answer:
AWS evaluates permissions using a deterministic 3-tier algorithm:
  1. Default Decision: Deny (everything is blocked implicitly).
  2. Check for Explicit Deny: AWS scans all attached identity policies, resource policies, permission boundaries, and SCPs. If any statement says "Effect": "Deny", the final answer is DENIED immediately.
  3. Check for Explicit Allow: If no explicit Deny was found, AWS checks if at least one statement says "Effect": "Allow". If yes → ALLOWED. If no → DENIED (by default).
