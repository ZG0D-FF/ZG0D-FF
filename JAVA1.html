Unit 01

JVM Architecture

The Java Virtual Machine (JVM) is an abstract machine — not physical hardware — that provides a runtime environment for executing Java bytecode. It enables Java's platform independence: write once, run anywhere.

Execution Pipeline

.java source → javac compiler → .class bytecode → JVM → Machine Code

What JVM Does

Loads code Verifies code Executes code Provides runtime env

JVM Memory Areas

01
Class (Method) Area — Stores per-class structures: runtime constant pool, field/method data, method code. Shared across all objects.
02
Heap — Runtime data area where objects are allocated. new keyword allocates here. Managed by Garbage Collector. Shared memory.
03
Stack — Stores method frames with local variables and partial results. Each thread has its own stack. Operates on LIFO ($\text{Last In, First Out}$).
04
PC Register — Stores the address of the JVM instruction currently being executed.
05
Native Method Stack — Holds all native (non-Java: C/C++) methods used in the application.

Heap vs Stack — Golden Comparison

FeatureHeapStack
StoresObjectsMethods / Frames
ScopeShared (all threads)Thread-specific
SizeDynamicFixed
ManagementGarbage CollectorAutomatic (LIFO)
Key triggernew keywordMethod call

Key Components

ClassLoader

Subsystem that loads .class files into JVM. Flow: Bootstrap → Extension → Application. First step every time a Java program runs.

Execution Engine

Contains a virtual processor, Interpreter (reads bytecode stream), and JIT Compiler (converts bytecode → machine code at runtime for speed 🔥).

JNI — Java Native Interface

Framework to communicate with applications written in C, C++, Assembly. Used for hardware access and OS-level operations.

JVM Analogy

JVM = Engine · Bytecode = Fuel · JIT = Turbo Boost · JRE = Full vehicle (JVM + libraries)

Constructors

A constructor is a special block of code, similar to a method, invoked automatically when an object is created using the new keyword. Its purpose is to initialize the object's state.

Rules

Same name as class No return type Cannot be abstract / static / final / synchronized Called automatically on new

Types

Default Constructor

No parameters. Compiler provides one automatically if you define none.

class A {
  A() {
    System.out.println("Default");
  }
}
Parameterized Constructor

Accepts arguments to assign values at object creation time.

class A {
  int x;
  A(int x) {
    this.x = x;
  }
}

Constructor Overloading

Multiple constructors with different parameter lists. Compiler differentiates by number and type of arguments.

class A {
  A() {}                          // default
  A(int x) {}                     // one param
  A(int x, int y) {}             // two params
  A(String s, int n) {}          // mixed types
}

Wrapping data and methods together into a single, secure unit. This achieves data hiding and improves security.

Expecting the Unexpected (System Safety Engine)

When a system interacts with the real world—like external sensors or network servers—things go wrong. An Exception is an unexpected runtime event that breaks the normal flow of the program.

Why Exception Handling?

Prevent crash 🛑 Maintain 100% uptime 🔄 Safe execution Graceful recovery

The Anatomy of a Safety Net

try { }

The Risk Zone ⚠️: You put the risky code in here (e.g., reading a sensor array, pinging a server).

catch { }

The Recovery Plan 🛠️: If the try block blows up, execution jumps here. You tell Java what to do to recover.

finally { }

The Cleanup Crew 🧹: Always executes, whether it crashed or not. Used to close connections or reset sensors.

class Calculator {

Unit 27

File I/O (Data Persistence System)

Your ArrayList only exists in the computer's temporary RAM. When you close the app, the roster disappears! File I/O permanently saves data to the hard drive so it isn't lost.

Streams (Data Flow Pipelines 🚰)

A sequence of data flow. InputStreams are for reading data into your program, and OutputStreams are for writing data out to a file.

FileOutputStream (Write Operation)

Writes raw bytes to a file. Because interacting with a hard drive is inherently risky (permissions, disk space), Java forces you to wrap this in a try-catch block. Always close your stream to free up memory!

try {
  FileOutputStream out = new FileOutputStream("save.txt");
  out.write(65); // Writes ASCII 'A'
  out.close();   // LOCK IT DOWN 🔒
} catch (Exception e) {
  System.out.println("Disk Error!");
}

Unit 29

Java GUI (Graphical User Interface)

A visual interface for user interaction that replaces the command line. To build this visual dashboard layer, Java gives you three main toolkits.

AWT, Swing & Applets

1. AWT (Abstract Window Toolkit)

The original GUI library. It is heavyweight and platform-dependent because it asks the underlying OS to draw components.

2. Swing (Most Important 🔥)

The modern upgrade built on AWT. It is lightweight, fully Java-based, and looks exactly the same on every device.

3. Applets (Deprecated ❌)

Building the very first window for your control panel.

Full Solution: The System Dashboard

import javax.swing.*;

class Dashboard {
    public static void main(String[] args) {

        // Step 1: Create JFrame (The Window)
        JFrame mainScreen = new JFrame("System Control");

        // Step 2: Create JLabel (The Text Display)
        JLabel statusLabel = new JLabel("Status: Online");

        // Set position (x, y, width, height)
        statusLabel.setBounds(50, 50, 150, 30);

        // Step 3: Add label to frame
        mainScreen.add(statusLabel);

        // Step 4: Frame settings
        mainScreen.setSize(300, 200);
        mainScreen.setLayout(null);

        // Step 5: Make visible (Turn the screen on!)
        mainScreen.setVisible(true);
    }
}
Unit 32

JDBC (Java Database Connectivity)

In Unit 4, we used File I/O for simple storage. But for thousands of records, we need a database. JDBC is the API that acts as a bridge, letting Java talk to systems like MySQL[cite: 3568, 3574].

The 4 Types of JDBC Drivers

Type 1: JDBC-ODBC Bridge

An old-school adapter that is platform-dependent. Mostly obsolete now.

Type 2: Native API

Uses native C/C++ libraries. Faster than Type 1 but complex to set up.

Type 3: Network Protocol

Uses a middle server (middleware) to reach the database. Very flexible for enterprises.

Type 4: Pure Java Driver 🔥

The Gold Standard: 100% Java, direct connection, and platform independent. This is the fastest and most used driver[cite: 3568].

Unit 33

The 5-Step Connection Process

To get Java to talk to a database, you must follow this strict 5-step sequence[cite: 3572, 3573].

01
Register the Driver — Load the driver class into memory (e.g., Class.forName()).
02
Establish Connection — Login to the DB using a URL, Username, and Password.
03
Create Statement — Build the object that will carry your SQL commands.
04
Execute Query — Send the SQL command and receive data in a ResultSet.
05
Close Connection — Always shut down the bridge to save system resources.
Unit 34

Integration & Assignment 9

Writing the "handshake" code to connect your Java program to a MySQL database safely using try-catch.

Full Solution: The JDBC Handshake

import java.sql.*;

class DatabaseConnect {
  public static void main(String[] args) {
    try {
      // Step 1: Register the MySQL Driver
      Class.forName("com.mysql.jdbc.Driver");

      // Step 2: Establish the Connection
      Connection con = DriverManager.getConnection(
        "jdbc:mysql://localhost:3306/jarvis_db",
        "dj_admin",
        "ironman123"
      );

      System.out.println("Connection Successful!");

      // Step 5: Close Connection
      con.close();
    } 
    catch (Exception e) {
      // Safety Net for wrong credentials or DB downtime
      System.out.println("Connection Failed!");
    }
  }
}
