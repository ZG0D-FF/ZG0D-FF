Problem #01
Sorting O(N²)

1. Bubble Sort with Swap Counter

💡 Memory Trick Think of heavy bubbles sinking to the bottom. Compare two neighbors at a time (j and j + 1). If the left one is bigger, swap them. After each full pass, the biggest number settles at the very end, so the next pass checks one less item (n - 1 - i).
bubble_sort.py 
nums = list(map(int, input("Enter numbers separated by space: ").split()))
n = len(nums)
swaps = 0

for i in range(n - 1):                  # Number of passes
    for j in range(n - 1 - i):          # Compare neighbors up to unsorted part
        if nums[j] > nums[j + 1]:       # If left is bigger than right
            nums[j], nums[j + 1] = nums[j + 1], nums[j]  # Swap them
            swaps += 1

print("Sorted list:", nums)
print("Total swaps:", swaps)

2. GCD and LCM (Euclidean Algorithm)

💡 Memory Trick In Euclid's algorithm, keep replacing (a, b) with (b, a % b) until b becomes 0. Whatever is left in a is the GCD. Then use the formula: $\text{LCM} = \frac{a \times b}{\text{GCD}}$.
gcd_lcm.py 
def find_gcd(a, b):
    while b != 0:
        a, b = b, a % b
    return a

num1 = int(input("Enter first number: "))
num2 = int(input("Enter second number: "))

gcd = find_gcd(num1, num2)
lcm = (num1 * num2) // gcd

print("GCD:", gcd)
print("LCM:", lcm)

⚠️ Exam Trap Callout Using single slash / for LCM results in a float (e.g. 72.0). Always use integer floor division // to preserve integer type.

12. Perfect Number Using Function

💡 Memory Trick Check every number i from 1 to n - 1. If n % i == 0, add it to the sum. If the sum equals n, it's a perfect number.

def sum_proper_divisors(n):
    total = 0

🔬 Deep Dive A: Fibonacci Series Using Recursion & 3D Call Stack Recursion Tree

The Core Idea: In Fibonacci, every number is the sum of the two numbers right before it: fib(n) = fib(n - 1) + fib(n - 2). You just need two stopping rules (base cases) so the recursion doesn't run forever: position 0 is 0, and position 1 is 1.

recursive_fibonacci.py 
def fib(n):
    if n == 0:
        return 0
    if n == 1:
        return 1
    return fib(n - 1) + fib(n - 2)

terms = int(input("Enter number of terms N: "))
total = 0

for i in range(terms):
    val = fib(i)
    print(val, end=" ")
    total += val

print("\nSum of terms:", total)

How the Loop and Call Stack Work Step-by-Step

If you enter 5, range(5) yields 0, 1, 2, 3, 4:

  • fib(0): Hits base case 1 $\rightarrow$ Returns 0 (Total = 0)
  • fib(1): Hits base case 2 $\rightarrow$ Returns 1 (Total = 1)
  • fib(2): Computes fib(1) + fib(0) = 1 + 0 $\rightarrow$ Returns 1 (Total = 2)
  • fib(3): Computes fib(2) + fib(1) = 1 + 1 $\rightarrow$ Returns 2 (Total = 4)
  • fib(4): Computes fib(3) + fib(2) = 2 + 1 $\rightarrow$ Returns 3 (Total = 7)

Final Output Printed: 0 1 1 2 3 | Sum of terms: 7

🔬 Deep Dive B: Under The Hood of #17 — ord(), chr() & ASCII Secret IDs ASCII Hardware

Computers don't actually know what letters are—they store purely binary numbers. Every character on your keyboard has a secret ID number called its ASCII (American Standard Code for Information Interchange) value.

1. ord(letter) — Order / ID Number

Turns a single character into its integer ASCII code.

ord('a') # Returns 97
ord('b') # Returns 98

2. chr(number) — Character

Turns an integer ASCII code back into a character.

chr(97)  # Returns 'a'
chr(98)  # Returns 'b'
chr(122) # Returns 'z'

🔬 Deep Dive C: Under The Hood of #12 — Perfect Numbers & Proper Divisors Divisor Theory

What is a "proper divisor"? A proper divisor of a positive integer $N$ is any positive divisor of $N$ strictly excluding $N$ itself.

Mechanical Walkthrough for $N = 6$

All positive whole numbers strictly smaller than $6$ are: $1, 2, 3, 4, 5$. We test the modulo $6 \pmod i$:

  • ✔ 6 % 1 == 0 → 1 is a proper divisor (Running sum = 1)
  • ✔ 6 % 2 == 0 → 2 is a proper divisor (Running sum = 1 + 2 = 3)
  • ✔ 6 % 3 == 0 → 3 is a proper divisor (Running sum = 3 + 3 = 6)
  • ✖ 6 % 4 == 2 → Remainder exists (Skipped)
  • ✖ 6 % 5 == 1 → Remainder exists (Skipped)
Sum of proper divisors = 1 + 2 + 3 = 6. Since sum == 6, 6 is a PERFECT NUMBER!

Contrast: Why is $N = 8$ NOT a Perfect Number?

Proper divisors of 8: $\{1, 2, 4\}$.
Sum = $1 + 2 + 4 = 7$.
Since $7 \ne 8$, 8 is deficient, not perfect.

Why range(1, n)? In Python, range(1, 6) automatically stops at 5 (one before 6). That mathematically guarantees we only check numbers strictly smaller than $N$, naturally eliminating $N$ from being added to the proper divisor accumulator.
