8051 MICROCONTROLLER MASTER GUIDE & LAB MANUAL

Core Architecture, Assembly Loops & Branching, Machine Cycles, Time Delays & Lab Experiments

8051 Microcontroller Specifications

  • Memory Capacity: 64KB RAM/ROM (maximum external memory space).
  • Data Bus: 8-bit bidirectional bus.
  • Address Bus: 16-bit (16 address lines addressing 216 = 65,536 bytes from 0000H to FFFFH).
  • I/O Ports: 4 I/O ports (P0, P1, P2, P3) providing 32 I/O lines (1 port = 8 bits).
  • Clock Frequency: Typically 11.0592 MHz or 12 MHz.
  • Machine Cycle: In standard 8051, 1 machine cycle requires 12 clock periods (T-states).
  • ALE: Address Latch Enable (demultiplexes Port 0).
  • PSEN: Program Store Enable (read strobe for external ROM).
  • Multiplexing: Lower order address and data lines (AD0 - AD7) are time-division multiplexed on Port 0.

1. Microprocessor vs Microcontroller

Microprocessor Microcontroller
Heart of a General Purpose Computer system. Heart of an Embedded System.
Only CPU on-chip; memory and I/O connected externally. CPU, internal RAM, ROM, timers, and I/O ports integrated on a single IC.
Large external circuit size; higher power consumption. Compact circuit; low power consumption; battery-friendly.
Based on Von Neumann architecture (unified code & data). Based on Harvard architecture (separate code and data memory spaces).

2. Basic Components & Pinout

  • On-Chip ROM: 4KB internal Flash/ROM.
  • On-Chip RAM: 128 bytes internal RAM (plus SFRs).
  • Timers: Two 16-bit timers/counters (Timer 0, Timer 1).
  • Serial Interface: Full-duplex UART (RXD on P3.0, TXD on P3.1).
  • Interrupt Sources: 6 interrupt vectors (Reset, 2 external INT0/INT1, 2 Timer TF0/TF1, 1 Serial RI/TI).

2. INTERNAL RAM ORGANIZATION & SCRATCHPAD MEMORY

The 128-Byte Internal RAM Organization

The standard 8051 on-chip data RAM contains 128 bytes mapped from address 00H to 7FH, partitioned into three functional regions:

  1. Register Banks (00H – 1FH): 32 bytes divided into 4 banks (Bank 0, 1, 2, 3) of 8 registers each (R0 through R7).
    • Bank selection is governed dynamically by the RS1 (PSW.4) and RS0 (PSW.3) bits in the Program Status Word.
    • Upon hardware reset, Bank 0 (addresses 00H–07H) is selected by default.
  2. Bit-Addressable RAM (20H – 2FH): 16 bytes providing 128 individually addressable bit locations numbered 00H to 7FH.
    • These locations are dual-purpose: they can be read or written as whole bytes (using addresses 20H–2FH) or bit-by-bit (using bit addresses 00H–7FH).
  3. General-Purpose Scratchpad RAM (30H – 7FH): 80 bytes of general-purpose read/write storage.
    • Used for runtime variables, look-up buffers, and user stack allocation.
    • In robust programming, the stack pointer (SP) is re-initialized to 2FH or 30H to prevent stack operations from trampling bit-addressable variables or secondary register banks!

RAM Locations 30H – 7FH as Scratch Pad

When all general-purpose registers R0–R7 are occupied, programmers utilize RAM addresses 30H–7FH as a high-speed scratchpad. Unlike registers, these locations can be read and written directly or indirectly without bank switching.

Example 5-10: Write a program to toggle port P1 a total of 200 times. Use RAM location 32H to hold the loop counter instead of registers R0–R7. 
        MOV P1, #55H        ; Initialize P1 with pattern 01010101B
        MOV 32H, #200       ; Load loop counter (200 decimal = C8H) into RAM 32H
LOP1:   CPL P1              ; Toggle all bits of Port 1
        ACALL DELAY         ; Wait for delay subroutine
        DJNZ 32H, LOP1      ; Decrement RAM 32H; jump to LOP1 if not zero!

Key Takeaway: The instruction DJNZ direct, rel can directly decrement any internal RAM location, allowing programmers to run counters directly in RAM without exhausting R0–R7.

3. THE 5 ADDRESSING MODES & INTERACTIVE OPERAND INSPECTOR

An Addressing Mode defines the mechanism the CPU utilizes to access an operand or source/destination data location. The 8051 supports five fundamental addressing modes:

1. Immediate Addressing Mode

In immediate addressing, the source operand is an explicit constant embedded directly within the instruction opcode stream in ROM. The data byte or word is preceded by the pound symbol #.

  • Can load 8-bit constants into Accumulator, B, or registers: MOV A, #25H, MOV R4, #62, MOV B, #40H.
  • Can load a 16-bit constant directly into the Data Pointer: MOV DPTR, #4521H (which loads DPH = 45H and DPL = 21H).
  • Illegal Value Trap: Immediate values loaded into 16-bit registers must not exceed 65535 (FFFFH). Writing MOV DPTR, #68975 produces an assembler syntax error!
  • EQU Directive: Programmers frequently use the EQU directive to assign descriptive symbols to immediate values: 
    Count   EQU 30              ; Assign constant 30 (1EH) to symbol Count
        ...
        MOV R4, #Count      ; R4 = 1EH
        MOV DPTR, #MYDATA   ; DPTR points to code ROM label MYDATA (e.g., 0200H)
        ORG 200H
MYDATA: DB "America"
  • Direct Port Output: Immediate constants can be written directly to physical I/O ports: MOV P1, #55H.

2. Register Addressing Mode

Register addressing involves manipulating data stored directly within CPU internal registers (A, B, R0–R7, DPTR, DPH, DPL).

  • Examples: MOV A, R0 (copy R0 into A), MOV R2, A, ADD A, R5, MOV R6, A.
  • 16-bit register splitting: MOV DPTR, #25F5H followed by MOV R7, DPL (R7 = F5H) and MOV R6, DPH (R6 = 25H).
  • Strict Rule 1 - Operand Size Matching: The source and destination registers must match in bit width. Writing MOV DPTR, A produces a fatal assembly error because DPTR is 16-bit while A is 8-bit.
  • Strict Rule 2 - No Register-to-Register Moves: Data transfer between two general-purpose registers is completely prohibited in 8051 machine code. Writing MOV R4, R7 is illegal! To copy R7 to R4, data must intermediate through Accumulator: MOV A, R7 then MOV R4, A.

3. Direct Addressing Mode

In direct addressing, the instruction operand specifies the absolute 8-bit RAM or SFR memory address. Notice there is no pound sign (#).

  • MOV R0, 40H copies the contents stored at internal RAM location 40H into R0 (contrast with MOV R0, #40H which loads the literal value 40H).
  • MOV 56H, A saves the Accumulator contents into RAM address 56H.
  • MOV A, 04H is identical to MOV A, R4 (when Bank 0 is active, RAM address 04H corresponds to Register R4).
  • Special Function Register (SFR) Access: SFRs located at 80H–FFH can be referenced interchangeably by their mnemonic name or their direct hexadecimal address:
    • MOV 0E0H, #55H is identical to MOV A, #55H.
    • MOV 0F0H, R0 is identical to MOV B, R0.
  • Stack Direct-Addressing Exclusivity: The 8051 stack instructions PUSH and POP support ONLY direct addressing!
    • PUSH A is strictly illegal and will not assemble!
    • Pushing Accumulator onto the stack must be written as PUSH 0E0H (or PUSH ACC).
    • Pushing register R5 onto the stack must be written as PUSH 05H.
Example 5-2: Write assembly code to push R5 and A onto the stack, then pop them back into R2 and B, such that Register B = Register A and Register R2 = Register R5. 
        PUSH 05             ; Push R5 onto stack (SP increments, RAM[SP] = R5)
        PUSH 0E0H           ; Push Register A onto stack (PUSH A is illegal!)
        POP  0F0H           ; Pop top of stack into Register B (B now equals A)
        POP  02             ; Pop top of stack into Register R2 (R2 now equals R5)

4. Register Indirect Addressing Mode

A register is employed as an active pointer holding the memory address of the target operand. In assembly, pointer indirection is denoted by the at-sign @.

  • Strict Pointer Restriction: For internal RAM access, ONLY registers R0 and R1 can serve as indirect pointers! Registers R2 through R7 cannot be used.
    • MOV A, @R0 (valid: moves data from RAM address pointed to by R0 into A).
    • MOV @R1, B (valid: moves B into RAM address pointed to by R1).
    • MOV A, @R2 (fatal assembly error: R2 cannot be a pointer!).
  • Dynamic vs Static Access: The decisive advantage of register indirect addressing is that memory access becomes dynamic. Because pointers can be incremented (`INC R0`) inside a loop, block transfers and memory clearing become possible. Direct addressing is static and cannot be looped!
Example 5-3: Copy 55H into RAM 40H–41H (Direct vs Indirect vs Loop) 
; (a) Direct Addressing (Static, no pointer)
        MOV A, #55H
        MOV 40H, A
        MOV 41H, A

; (b) Register Indirect without Loop
        MOV A, #55H
        MOV R0, #40H        ; Load pointer R0 with start address 40H
        MOV @R0, A          ; RAM[40H] = 55H
        INC R0              ; R0 increments to 41H
        MOV @R0, A          ; RAM[41H] = 55H

; (c) Register Indirect with DJNZ Loop
        MOV A, #55H
        MOV R0, #40H        ; Load RAM pointer
        MOV R2, #02         ; Counter = 2 iterations
AGAIN:  MOV @R0, A          ; Copy 55H to RAM[R0]
        INC R0              ; Advance pointer
        DJNZ R2, AGAIN      ; Repeat until counter = 0
Example 5-4: Clear 16 RAM locations starting at 60H 
        CLR A               ; A = 0
        MOV R1, #60H        ; Pointer R1 = 60H
        MOV R7, #16         ; Counter = 16 locations (60H to 6FH)
AGAIN:  MOV @R1, A          ; Clear byte pointed to by R1
        INC R1              ; Increment pointer
        DJNZ R7, AGAIN      ; Loop until R7 = 0
Example 5-5: Block copy 10 bytes from 35H to 60H 
        MOV R0, #35H        ; Source pointer
        MOV R1, #60H        ; Destination pointer
        MOV R3, #10         ; Counter = 10 bytes
BACK:   MOV A, @R0          ; Read byte from source RAM
        MOV @R1, A          ; Write byte to destination RAM
        INC R0              ; Advance source pointer
        INC R1              ; Advance destination pointer
        DJNZ R3, BACK       ; Loop 10 times

5. Indexed Addressing Mode & On-Chip ROM Access

Indexed addressing is utilized to read fixed constant lookup tables, string literals, and calibration factors stored in Program ROM. The target physical address is calculated as the sum of a base pointer register plus an 8-bit offset index in Accumulator A.

  • Instruction: MOVC A, @A+DPTR or MOVC A, @A+PC (where "C" signifies Code memory).
  • $$\text{Physical ROM Address} = \text{DPTR} + \text{Accumulator (A)}$$
  • Enables lookup tables that execute in $O(1)$ constant time with zero branch prediction penalty.
Example 5-6: Reading string "USA" burned in ROM at 200H 
        ORG 0000H
        MOV DPTR, #200H     ; DPTR = 200H (base table address)
        CLR A               ; A = 0 (offset 0 -> character 'U')
        MOVC A, @A+DPTR     ; Read ROM[200H]; A = 55H ('U')
        MOV R0, A           ; R0 = 55H
        INC DPTR            ; DPTR = 201H
        CLR A               ; A = 0 (offset 0 -> character 'S')
        MOVC A, @A+DPTR     ; Read ROM[201H]; A = 53H ('S')
        MOV R1, A           ; R1 = 53H
        INC DPTR            ; DPTR = 202H
        CLR A               ; A = 0
        MOVC A, @A+DPTR     ; Read ROM[202H]; A = 41H ('A')
        MOV R2, A           ; R2 = 41H
HERE:   SJMP HERE

        ORG 200H
MYDATA: DB "USA"            ; String burned in code space at 0200H
        END
Example 5-8: Real-Time Look-Up Table Square Generator ($y = x^2$) 
        ORG 0000H
        MOV DPTR, #300H     ; Base pointer to square lookup table
        MOV A, #0FFH
        MOV P1, A           ; Configure Port 1 as input port
BACK:   MOV A, P1           ; Read input number x (0 to 9) from Port 1
        MOVC A, @A+DPTR     ; Fetch pre-computed square x^2 from ROM table!
        MOV P2, A           ; Output result to Port 2 LEDs/DAC
        SJMP BACK           ; Repeat indefinitely

        ORG 300H
XSQR_TABLE: DB 0, 1, 4, 9, 16, 25, 36, 49, 64, 81
        END

External Data Memory Access (MOVX)

The 8051 implements a strict Harvard architecture with completely independent physical code and data spaces. When an application requires external RAM (up to 64KB), the MOVX (Move External) instruction is mandatory:

  • MOVX A, @DPTR : Reads 1 byte from 16-bit external data address in DPTR into A.
  • MOVX @DPTR, A : Writes 1 byte from A to 16-bit external data address in DPTR.
  • MOVX A, @R0 / MOVX @R0, A : 8-bit paged external RAM access (Port 0 carries address/data, Port 2 carries page).
  • Total memory space in 8051 is 128KB (64KB Code ROM + 64KB External Data RAM). Code and data cannot be co-located or shared!

4. SPECIAL FUNCTION REGISTERS (SFR) ARCHITECTURE & ADDRESS MAP

Special Function Registers (SFRs) occupy the upper memory address space from 80H to FFH. These registers configure, monitor, and drive all internal peripherals: I/O ports, timers/counters, serial UART, interrupt controller, and CPU status flags.

  • Sparsely Populated: Not all 128 addresses in 80H–FFH are implemented. Unused addresses are reserved by the silicon manufacturer and must never be accessed by user software!
  • Bit-Addressable SFR Rule: Only SFR addresses whose hexadecimal address ends in 0 or 8 (i.e., addresses divisible by 8) are bit-addressable (e.g., 80H, 88H, 90H, 98H, A0H, A8H, B0H, B8H, D0H, E0H, F0H). All other SFRs are strictly byte-addressable!

; (a) Using Mnemonic Register Names:
        MOV A, #55H         ; Load immediate 55H into A
        MOV P1, A           ; Output 55H to Port 1
        MOV P2, A           ; Output 55H to Port 2

5. BIT-ADDRESSABLE RAM (20H–2FH) & THE BOOLEAN PROCESSING ENGINE

A crowning architectural hallmark of the 8051 is its dedicated hardware Boolean Processing Engine. While conventional microprocessors must execute cumbersome multi-instruction mask-and-shift routines (`AND`, `OR`, `XOR`) to inspect or alter a single I/O pin or flag, the 8051 provides atomic 1-cycle single-bit instructions capable of setting, clearing, inverting, and testing individual bits directly!

Bit-Addressable RAM Structure (20H to 2FH)

A block of 16 bytes of internal RAM (from byte address 20H to 2FH) is wired to the bit processing engine. Because each byte consists of 8 bits, this block yields exactly 128 bit addresses numbered from 00H to 7FH:

  • The lowest bit (D0) of RAM byte 20H has bit address 00H; bit D7 of 20H has bit address 07H.
  • The lowest bit (D0) of RAM byte 2FH has bit address 78H; bit D7 of 2FH has bit address 7FH.

Decoding Mathematical Formula: Bit Address ➔ Byte Address & Bit Position

To determine exactly which RAM byte and bit position an arbitrary bit address $B$ ($00\text{H} \le B \le 7\text{F}\text{H}$) belongs to, evaluate:

$$\text{RAM Byte Address (Hex)} = 20\text{H} + \left\lfloor \frac{B}{8} \right\rfloor$$ $$\text{Bit Position inside Byte} = \text{D}_k \quad \text{where } k = B \pmod 8$$

Example 5-11: Practical Bit Address Decoding Table

SETB 42H 42H (66 decimal) $66 / 8 = 8$ (08H) $66 \pmod 8 = 2$ $20\text{H} + 8 = \mathbf{28H}$ D2 of RAM 28H
CLR 67H 67H (103 decimal) $103 / 8 = 12$ (0CH) $103 \pmod 8 = 7$ $20\text{H} + \text{0CH} = \mathbf{2CH}$ D7 of RAM 2CH

SETB 05 05 decimal (05H) $5 / 8 = 0$ (00H) $5 \pmod 8 = 5$ $20\text{H} + 0 = \mathbf{20H}$ D5 of RAM 20H

Disambiguation: Byte Addresses 00H–7FH vs Bit Addresses 00H–7FH

CRITICAL EXAM TRAP: Notice that the numerical range 00H to 7FH represents two completely different entities in the 8051:

  • As Byte Addresses: 00H–7FH addresses all 128 bytes of internal RAM (accessed via byte instructions such as MOV A, 25H).
  • As Bit Addresses: 00H–7FH addresses the 128 individual bits mapped exclusively inside RAM bytes 20H through 2FH (accessed via single-bit instructions such as SETB 25H).
  • The CPU automatically distinguishes between byte vs bit references by analyzing the opcode: byte instructions access the byte; bit instructions access the bit!

I/O Port Single-Bit Addressing (Ports P0 to P3)

Because physical I/O ports P0, P1, P2, and P3 are bit-addressable SFRs, individual pins can be controlled independently without modifying adjacent pins:

  • Syntax: SETB Px.y where $x$ is port 0–3 and $y$ is pin bit 0–7 (e.g., SETB P1.5).
  • When assembled, SETB P1.5 compiles directly to bit address 95H:
    • Port 0 bits: 80H to 87H (P0.0 = 80H, P0.7 = 87H)
    • Port 1 bits: 90H to 97H (P1.0 = 90H, P1.7 = 97H)
    • Port 2 bits: A0H to A7H (P2.0 = A0H, P2.7 = A7H)
    • Port 3 bits: B0H to B7H (P3.0 = B0H, P3.7 = B7H)

        CLR  PSW.3          ; RS0 = 0

While the 8051 has JC and JNC for the carry flag, it has no direct `JOV` instruction. Instead, programmers test the bit-addressable OV flag (bit PSW.2 / D2H) using JB:

        JB PSW.2, TARGET    ; Jump to TARGET if Overflow Flag (OV) is set to 1!

        MOV C, P1.7         ; Copy logic state of pin P1.7 into Carry Flag C
        MOV 05H, C          ; Copy Carry Flag C into bit address 05H (D5 of RAM 20H)

        CLR  06             ; Clear RAM bit address 06

NEXT:   ...
Example 5-15: Even / Odd Parity Check of RAM Location 37H

Recall that bit D0 of any binary integer indicates whether the number is even ($D_0 = 0$) or odd ($D_0 = 1$):

        MOV A, 37H          ; Load RAM location 37H into Accumulator
        JNB ACC.0, YES      ; Is bit D0 equal to 0? If so, number is even -> Jump!
        INC A               ; If odd, increment to make it even
YES:    MOV P2, A           ; Output even number to Port 2

  • Example 5-20: Industrial Oven Thermal Alarm Monitor 
    OVEN_HOT BIT P2.3   ; Logic 1 indicates oven overheating

6. EXTRA 128-BYTE ON-CHIP RAM IN 8052 & MEMORY DISAMBIGUATION

The standard 8051 contains 128 bytes of on-chip RAM (00H–7FH). However, enhanced members of the MCS-51 family such as the 8052 feature 256 bytes of on-chip data RAM. This extra 128-byte block is mapped to addresses 80H through FFH—the exact same numerical range assigned to the SFRs!

Addressing Disambiguation: Direct vs Indirect Memory Access

To avoid hardware collisions in the 8052 between the Upper 128-byte RAM and the Special Function Registers, the CPU decodes the addressing mode utilized by the instruction:

  • Direct Addressing Mode ➔ Accesses SFRs:
    Writing MOV 90H, #55H (or MOV P1, #55H) writes directly to the Port 1 SFR latch.
  • Register Indirect Addressing Mode ➔ Accesses Upper 128-Byte RAM:
    When register R0 or R1 contains an address between 80H and FFH, using indirection (MOV @R0, A or MOV A, @R1) writes to or reads from the internal physical RAM, completely bypassing the SFR!
Example 5-27: Copy String from Code ROM into 8052 Upper RAM starting at 80H and Echo to Port 0 
        ORG 0000H
        MOV DPTR, #MYDATA   ; DPTR points to lookup string in code ROM
        MOV R1, #80H        ; Pointer R1 = 80H (targets 8052 upper RAM via indirection!)

B1:     CLR A               ; A = 0
        MOVC A, @A+DPTR     ; Read character from program ROM
        MOV @R1, A          ; Store into upper RAM address pointed to by R1!
        MOV P0, A           ; Echo copy to Port 0 (uses direct addressing)
        JZ  EXIT            ; If character is NULL terminator (0), exit!
        INC DPTR            ; Advance ROM pointer
        INC R1              ; Advance Upper RAM pointer
        SJMP B1             ; Loop until string finished

EXIT:   SJMP $              ; Halt in infinite loop

        ORG 0300H
MYDATA: DB "The Promise of World Peace", 0
        END

Crucial Insight: In the instruction MOV @R1, A where R1 = 80H, the byte enters physical scratchpad RAM location 80H. It does NOT overwrite Port 0 (which also resides at 80H), because Port 0 can only be altered through direct addressing (as demonstrated by MOV P0, A)!

4. LOOPING & NESTED LOOPS IN 8051

1. Fundamental Loop Structure: DJNZ

Repeating a sequence of instructions a set number of times is called a loop. In 8051 assembly, loops are driven by the DJNZ (Decrement and Jump if Not Zero) instruction:

  • Syntax: DJNZ reg, Label
  • Operation: The specified register is decremented by 1. If the updated value is not zero, CPU jumps to the target address referred to by the label. If the value reaches zero, execution falls through to the next sequential instruction.
  • Counter Registers: Any register R0–R7 or direct internal RAM address can be used as the counter.
  • Maximum Single-Loop Count: An 8-bit register holds a maximum value of 255 (0FFH). Therefore, a single register loop can iterate at most 255 times.

Example: Adding Value 3 to ACC 10 Times

; This program adds value 3 to the ACC ten times
    MOV A, #0       ; A = 0, clear accumulator
    MOV R2, #10     ; Load loop counter R2 = 10
AGAIN:
    ADD A, #03      ; Add 03 to ACC
    DJNZ R2, AGAIN  ; Decrement R2; repeat until R2 = 0
    MOV R5, A       ; Save final sum in R5 (A = 30)

2. Nested Loops (Repeating More Than 256 Times)

When an action must be repeated more than 255 times, a loop inside a loop (nested loop) is used. Multiple registers are employed to hold the inner and outer counts.

Example: Complementing ACC 700 Times

Since 700 > 255, we factor 700 into 10 × 70 = 700:

    MOV A, #55H     ; Initialize A with 55H
    MOV R3, #10     ; R3 = 10 (Outer loop counter)
NEXT:
    MOV R2, #70     ; R2 = 70 (Inner loop counter)
AGAIN:
    CPL A           ; Complement Accumulator bits
    DJNZ R2, AGAIN  ; Repeat inner loop 70 times
    DJNZ R3, NEXT   ; Decrement outer loop; repeat 10 times

Result: The inner instruction CPL A executes exactly 10 × 70 = 700 times.

5. CONDITIONAL & UNCONDITIONAL JUMPS

1. Conditional Jumps

Conditional jumps transfer control to a label only if a specified condition is satisfied. In 8051, all conditional jumps are SHORT JUMPS, meaning the target address must lie within -128 to +127 bytes of the program counter (PC).

A. Jump Based on Accumulator (JZ, JNZ):

  • JZ label : Jump if Accumulator is zero ($A = 0$).
  • JNZ label : Jump if Accumulator is not zero ($A \neq 0$).
  • Important: JZ and JNZ evaluate only Register A; they cannot directly test R0–R7 or memory!
; Determine if R5 contains the value 0. If so, put 55H in it:
    MOV A, R5       ; Copy R5 to Accumulator
    JNZ NEXT        ; Jump if A is not zero
    MOV R5, #55H    ; If A was zero, load 55H into R5
NEXT: ...

B. Jump Based on Carry Flag (JC, JNC):

  • JC label : Jump if Carry Flag is set ($CY = 1$).
  • JNC label : Jump if No Carry ($CY = 0$).
; Find the sum of 79H, F5H, and E2H. Store sum in R0 and carry in R5:
    MOV A, #0       ; Clear A
    MOV R5, A       ; Clear R5 (carry accumulator)
    ADD A, #79H     ; A = 79H, CY = 0

    ADD A, #0F5H    ; A = 79H + F5H = 6EH, CY = 1
    JNC N_2         ; Jump if CY = 0
    INC R5          ; Carry generated: R5 = 1

N_2:
    ADD A, #0E2H    ; A = 6EH + E2H = 50H, CY = 1
    JNC OVER        ; Jump if CY = 0
    INC R5          ; Carry generated: R5 = 2
OVER:
    MOV R0, A       ; Final result: R0 = 50H (low byte), R5 = 02H (high byte)

Complete 8051 Conditional Jumps Reference Table

JNZ target $A \neq 0$ Jump if Accumulator is non-zero

2. Unconditional Jumps: LJMP vs SJMP

  • LJMP (Long Jump - 3 Bytes):
    Byte 1 = Opcode (02H), Bytes 2 & 3 = 16-bit target address.
    Can jump unconditionally to any location within the entire 64KB code space (0000H to FFFFH).
  • SJMP (Short Jump - 2 Bytes):
    Byte 1 = Opcode (80H), Byte 2 = 8-bit signed relative displacement (relative to the PC of the instruction following the jump).
    Displacement spans -128 bytes backward to +127 bytes forward.

Calculating Short Jump Target Addresses

Target Address = (PC of instruction immediately below jump) + 8-bit signed relative offset

If the target address lies outside $-128$ to $+127$ bytes, the assembler throws an "Address Out of Range" error.

7. REGISTER BANKS, STACK ARCHITECTURE & COLLISION ENGINEERING

8051 Stack Architecture & The Stack Pointer (SP)

The stack is a dynamic Last-In, First-Out (LIFO) section of internal data RAM utilized by the CPU to save return addresses during subroutine calls (`LCALL`/`ACALL`), handle interrupt contexts, and temporarily preserve register contents (`PUSH`/`POP`).

  • 8-Bit Stack Pointer (SP): The Stack Pointer is an 8-bit Special Function Register located at direct address 81H (byte-only addressable, reset value = 07H).
  • Pre-Increment on PUSH: When data is pushed onto the stack, the 8051 increments SP first ($SP = SP + 1$), and then writes the byte to RAM location $[SP]$. (Notice this is the direct opposite of x86 processors which decrement SP!)
  • Post-Decrement on POP: When data is popped off the stack, the 8051 reads the byte from RAM location $[SP]$ into the target register, and then decrements SP ($SP = SP - 1$).

The Stack Collision Hazard & Register Bank Overlap

CRITICAL ARCHITECTURAL PITFALL: Upon hardware reset, the Stack Pointer automatically initializes to 07H:

  • Because the 8051 pre-increments SP, the very first pushed byte lands at physical RAM address 08H.
  • However, RAM addresses 08H to 0FH are physically assigned to Register Bank 1!
  • Continuing to push bytes past 0FH will trample Register Bank 2 (10H–17H), Register Bank 3 (18H–1FH), and eventually corrupt Bit-Addressable RAM (20H–2FH)!
  • If your program utilizes Register Bank 1 or bit variables, leaving SP at 07H will cause catastrophic data corruption!

Standard Solution - Relocating the Stack Pointer: At the very start of the program, relocate SP to the general-purpose scratchpad RAM area: 

        MOV SP, #2FH        ; Initialize SP to 2FH
                            ; The very first PUSH will now safely write into RAM address 30H!

        MOV R1, #12H        ; R1 = 12H

        PUSH 6              ; SP increments to 08H; RAM[08H] = 25H
        PUSH 1              ; SP increments to 09H; RAM[09H] = 12H

Subroutines: LCALL vs ACALL and Return Mechanism

  • LCALL (Long Call - 3 Bytes / 2 MC):
    Calls subroutines located anywhere within the entire 64KB program memory space. Pushes the 16-bit address of the next instruction onto stack (low-order byte first into $[SP+1]$, high-order byte second into $[SP+2]$). SP increments by 2.
  • ACALL (Absolute Call - 2 Bytes / 2 MC):
    Target address must reside within the same 2KB page (11-bit offset address). Saves 1 byte of program ROM for every subroutine call!
  • RET (Return from Subroutine - 1 Byte / 2 MC):
    Terminates every subroutine. Pops top two bytes from stack into Program Counter (high-order byte first, low-order byte second). SP decrements by 2, resuming execution at the caller's next instruction.
  • Matching PUSH/POP Rule: Any registers pushed inside a subroutine must be popped in exact reverse order prior to executing `RET`. Leaving an unpopped byte causes `RET` to pop data into the PC, crashing the CPU!

7. MACHINE CYCLES & TIME DELAY ENGINEERING

1. Machine Cycle Basics & 11.0592 MHz Crystal

The time taken by the CPU to execute an instruction is measured in Machine Cycles (MC):

  • In the standard 8051 (e.g., Atmel AT89C51), 1 Machine Cycle = 12 oscillator clock periods.
  • For an 11.0592 MHz crystal frequency:
    $$\text{Machine Cycle Frequency} = \frac{11.0592\text{ MHz}}{12} = 921.6\text{ kHz}$$ $$\text{Machine Cycle Period } (T_{MC}) = \frac{1}{921.6\text{ kHz}} = \mathbf{1.085\,\mu\text{s}} \quad (1085\text{ ns})$$

Instruction Execution Times Table (at 11.0592 MHz)

Instruction Machine Cycles (MC) Execution Time (T = MC × 1.085 μs)
MOV R3, #55H 1 MC 1 × 1.085 μs = 1.085 μs
DEC R3 1 MC 1 × 1.085 μs = 1.085 μs
NOP 1 MC 1 × 1.085 μs = 1.085 μs
DJNZ R2, target 2 MC 2 × 1.085 μs = 2.170 μs
LJMP / SJMP 2 MC 2 × 1.085 μs = 2.170 μs
RET 2 MC 2 × 1.085 μs = 2.170 μs
MUL AB / DIV AB 4 MC 4 × 1.085 μs = 4.340 μs

2. Delay Calculation Engineering: 3 Classic Patterns

A. Simple Single Loop Delay:

DELAY: MOV R3, #200     ; 1 MC
HERE:  DJNZ R3, HERE    ; 2 MC (repeats 200 times)
       RET              ; 2 MC

$$\text{Total Time} = [(200 \times 2) + 1 + 2] \times 1.085\,\mu\text{s} = [400 + 3] \times 1.085\,\mu\text{s} = \mathbf{436.255\,\mu\text{s}}$$

Coding Tip: An endless pause can be coded cleanly as HERE: SJMP HERE or simply SJMP $ (where $ denotes current PC).

B. Increasing Delay Using NOPs:

DELAY: MOV R3, #250     ; 1 MC
HERE:  NOP              ; 1 MC
       NOP              ; 1 MC
       NOP              ; 1 MC
       NOP              ; 1 MC
       DJNZ R3, HERE    ; 2 MC (Loop takes 1+1+1+1+2 = 6 MC per iteration)
       RET              ; 2 MC

$$\text{Loop Time} = 250 \times 6 \times 1.085\,\mu\text{s} = 1627.5\,\mu\text{s}$$ $$\text{Total Delay} = 1627.5\,\mu\text{s} + (1 + 2) \times 1.085\,\mu\text{s} = \mathbf{1630.755\,\mu\text{s}}$$

C. Large Delay with Nested Loops:

DELAY: MOV R2, #200     ; 1 MC
AGAIN: MOV R3, #250     ; 1 MC
HERE:  NOP              ; 1 MC
       NOP              ; 1 MC
       DJNZ R3, HERE    ; 2 MC (Inner loop = 4 MC x 250 = 1000 MC = 1085 µs)
       DJNZ R2, AGAIN   ; 2 MC (Repeats inner loop 200 times)
       RET              ; 2 MC

$$\text{Total Delay} \approx [200 \times (250 \times 4 + 3)] \times 1.085\,\mu\text{s} \approx \mathbf{217,651\,\mu\text{s} \approx 0.218\text{ seconds}}$$

8. COMPREHENSIVE 8051 INSTRUCTION SET REFERENCE

A. Data Transfer Instructions

  • MOV A, Rn / MOV Rn, A : Register to accumulator transfer.
  • MOV A, #data / MOV Rn, #data : Immediate data load.
  • MOV direct, direct : Direct RAM to direct RAM transfer.
  • MOVX A, @DPTR / MOVX @DPTR, A : External data RAM access.
  • MOVC A, @A+DPTR / MOVC A, @A+PC : Program memory (ROM) code lookup.
  • PUSH direct / POP direct : Stack operations.
  • XCH A, Rn / XCHD A, @Ri : Data and lower nibble exchanges.

B. Arithmetic Instructions

  • ADD A, operand / ADDC A, operand : Addition with or without carry.
  • SUBB A, operand : Subtraction with borrow.
  • MUL AB : Unsigned 8-bit multiply ($A \times B$; low byte in A, high byte in B).
  • DIV AB : Unsigned 8-bit divide ($A / B$; quotient in A, remainder in B).
  • DA A : Decimal adjust Accumulator after BCD addition.
  • INC operand / DEC operand : Increment / Decrement.

C. Logical Instructions

  • ANL dest, src : Bitwise AND.
  • ORL dest, src : Bitwise OR.
  • XRL dest, src : Bitwise Exclusive-OR.
  • CLR A / CPL A : Clear / 1's complement Accumulator.
  • RL A / RR A : Rotate left / right without carry.
  • RLC A / RRC A : Rotate left / right through carry.
  • SWAP A : Swap upper and lower nibbles of Accumulator.

D. Boolean & Bit Manipulation

  • CLR C / SETB C / CPL C : Clear, set, or complement carry bit.
  • CLR bit / SETB bit / CPL bit : Clear, set, or complement direct bit.
  • ANL C, bit / ORL C, bit : Boolean logic on carry flag.
