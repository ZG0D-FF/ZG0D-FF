# Information Theory (Slides 1–22) — Lucidified Notes
> Core Idea of the whole chapter:
> Information is simply a way of measuring how much uncertainty gets reduced when something happens.
## Slide 1 — What is this chapter about?
This chapter has four connected ideas.
* Uncertainty and Information
Why some events feel "more informative" than others.
* Self Information
Information contained in a single event.
* Mutual Information
How much one event tells us about another.
* Average Mutual Information
Average information shared between two random variables.
Think of it as climbing a staircase.

## Slides 2–4 — Why does uncertainty become information?
The slides compare three sentences.

| Statement | Probability | Information |
| --- | --- | --- |
| Sun rises in East | Almost 1 | Almost none |
| Phone rings next hour | Medium | Medium |
| Snow in Delhi | Very low | Very high |
### Why?
Imagine someone tells you:
> "The sun will rise tomorrow."
Your reaction?
> "Obviously."
Nothing new.
Now someone says,
> "It will snow in Delhi."
Now you're surprised.
That surprise is exactly what these slides call information.
## Golden Rule
> Less probable event → More information.
Why?
Because before the event happened, there was much more uncertainty.

## Slide 4 — Self Information
Now the slides convert intuition into mathematics.
For an event
X=xiX=x_iX=xi
Self-information is
I(xi)=log(1P(xi))=−logP(xi)I(x_i)=\log\left(\frac1{P(x_i)}\right)=-\log P(x_i)I(xi)=log(P(xi)1)=−logP(xi)
This formula measures the information contained in one specific event.
## Break the formula
Suppose
P=0.5
Then
$$I=-\log_2(0.5)=1\text{ bit}$$
Suppose
$$P=0.25$$
Then
$$I=-\log_2(0.25)=2\text{ bits}$$
Notice something beautiful.

| Probability | Self Information |
| --- | --- |
| 1 | 0 bits |
| 0.5 | 1 bit |
| 0.25 | 2 bits |
| 0.125 | 3 bits |
Every time probability halves,
information increases by one bit.
### Why "bit"?
The slide says:
* Base 2 → bits
* Base e → nats
For exams, unless stated otherwise, use base 2.

## Example 2 — Memoryless Source
The slide introduces an important word.
### Memoryless
Each toss does not remember previous tosses.
Every toss is independent.
Suppose we observe 3 tosses.
Possible outcomes:
* HHH
* HHT
* HTH
* HTT
* THH
* THT
* TTH
* TTT
There are
$$2^3=8$$
possible sequences.
Each has probability
$$2^{-3}=\frac18$$
Information becomes
$$I=-\log_2\left(\frac18\right)=3\text{ bits}$$
Notice
3 tosses require 3 bits.
Exactly matching intuition.
## Example 3 — Two Independent Sources
Source A gives one bit.
Source B gives one bit.
Together they form Source C.
Since they're independent,
P(C)=P(A)P(B)=0.5×0.5=0.25P(C)=P(A)P(B)=0.5\times0.5=0.25P(C)=P(A)P(B)=0.5×0.5=0.25
Information becomes
I(C)=−log2(0.25)=2 bitsI(C)=-\log_2(0.25)=2\text{ bits}I(C)=−log2(0.25)=2 bits
### Big observation
Two independent 1-bit sources
become
2 bits.
Nothing mysterious happened.
Information simply added.
## Slide 8 — Why do we use logarithm?
This slide answers a famous question.
Without logarithm,
independent probabilities multiply.
0.5×0.5=0.250.5\times0.5=0.250.5×0.5=0.25
But information should add.
1+1=21+1=21+1=2
The logarithm converts multiplication into addition.
log(ab)=loga+logb\log(ab)=\log a+\log blog(ab)=loga+logb
This is exactly why Shannon chose logarithms.
### Memory Trick
> Probability multiplies.
> Log converts multiplication into addition.
> Therefore information adds.
This is one of the most important ideas in the chapter.
## Slides 9–13 — Mutual Information
Until now,
we measured information inside one event.
Now we ask a new question.
> If I observe Y, how much does it tell me about X?
This is Mutual Information.
## Example intuition
Suppose
* X = What was transmitted
* Y = What was received
After seeing Y,
can we guess X better?
That improvement is mutual information.

## Slide 11 — Formula
The definition is
I(xi;yj)=log(P(xi∣yj)P(xi))I(x_i;y_j)=\log\left(\frac{P(x_i|y_j)}{P(x_i)}\right)I(xi;yj)=log(P(xi)P(xi∣yj))
Read it in words.
> Information equals
> "New probability after observing Y"
> divided by
> "Old probability before observing Y."
### Interpretation
If observing Y makes X much more likely,
the ratio becomes large.
Large ratio
→ Large information.
## Slide 12 — Symmetry
The slide proves
I(xi;yj)=I(yj;xi).I(x_i;y_j)=I(y_j;x_i).I(xi;yj)=I(yj;xi).
Meaning
Information shared between X and Y
is identical in either direction.
Think of it like this.
If knowing your roll number identifies your exam paper,
then your exam paper also identifies your roll number.
The shared information is the same.

# The Big Picture — Slides 1–26
This whole section is basically answering one question:
> **How can we represent source symbols using as few bits as possible, while still being able to decode them unambiguously?**
The progression is:
**Variable-length codes → Prefix condition → Kraft inequality → Source coding theorem → Efficiency → Huffman coding → Block coding**

## 1. Why Variable-Length Codes?
Suppose a source produces symbols with different probabilities.
Some symbols occur **very frequently**, while others are **rare**.
It would be wasteful to give every symbol the same number of bits.
Instead, we can do this:
* Frequent symbol → **short codeword**
* Rare symbol → **long codeword**
For example:

| Symbol | Probability | Code  |
| ------ | ----------: | ----- |
| A      |        high | `0`   |
| B      |      medium | `10`  |
| C      |         low | `110` |
So instead of using the same number of bits for everyone, we save bits on average.
That is the basic idea behind **variable-length coding**.
But there is a problem:
### How do we know where one codeword ends?
Suppose:
* A = `0`
* B = `01`
Now if we receive:
`01`
Is it:
**B**
or
**A followed by something?**
The code boundaries become ambiguous.
This leads directly to **prefix codes**.

## 2. Prefix Code
Look at Slide 3:

| Letter | Codeword |
| ------ | -------- |
| A      | `00`     |
| B      | `010`    |
| C      | `011`    |
| D      | `100`    |
| E      | `101`    |
| F      | `110`    |
| G      | `1110`   |
| H      | `1111`   |
The important observation is:
> **No codeword is the beginning of another codeword.**
For example:
* `00` → nobody else starts with `00`
* `010` → nobody else has `010...`
* `1110` → nobody else starts with `1110`
Therefore, once the received bits match a complete codeword, we immediately know the symbol.
### Example
Suppose the received stream is:
`0101111`
Look at the beginning:
`010` → B
Remaining:
`1111` → H
So:
**010 | 1111 → B H**
No guessing is required.

## 3. Why "Prefix" Matters
A **prefix** simply means:
> The beginning portion of a sequence.
For example:
`1011`
has prefixes:
* `1`
* `10`
* `101`
* `1011`
So if we had:
* A = `10`
* B = `101`
then `10` is a prefix of `101`.
That violates the prefix condition.
Therefore:
> **Prefix condition = no complete codeword can be the beginning of another codeword.**
Because of this property, the code is also called an:
> **Instantaneous code**
Why "instantaneous"?
Because once the complete codeword arrives, we can **immediately decode it**.

## 4. Kraft Inequality
Now the slides ask something slightly different.
Instead of asking:
> "Is this particular code a prefix code?"
we ask:
> **"Can a prefix code with these codeword lengths even exist?"**
That's what **Kraft inequality** tells us.
For a binary prefix code:
$$
\boxed{\sum_{k=1}^{L}2^{-n_k}\leq1}
$$
where \(n_k\) is the length of the \(k\)-th codeword.
For an alphabet of size \(M\):
$$
\boxed{\sum_{k=1}^{L}M^{-n_k}\leq1}
$$
### What should you remember?
Don't just memorize the equation.
Its meaning is:
> **The proposed codeword lengths must satisfy this inequality for a prefix code to exist.**
And importantly, the slide says this condition is **necessary and sufficient**.
So:
$$
\boxed{\text{Kraft condition satisfied} \iff \text{prefix code can exist}}
$$
for the stated setting.

## 10. Huffman Coding
Now comes the practical question:
> **How do we actually construct such an efficient variable-length prefix code?**
The slides introduce:
## Huffman Coding
Huffman coding uses the source probabilities.
Its goal is:
> Construct a prefix code with minimum average number of bits.
So Huffman coding simultaneously aims for:
1. **Prefix condition**
2. **Minimum average code length**

## 11. The Huffman Idea
The procedure is very intuitive.
### Step 1 — Arrange probabilities
Put symbols in decreasing probability order.
For example:
$$
0.37,\ 0.33,\ 0.16,\ 0.07,\ 0.04,\ 0.02,\ 0.01
$$
### Step 2 — Pick the two smallest
The two smallest are:
$$
0.01,\quad0.02
$$
Combine them:
$$
0.01+0.02=0.03
$$
Now treat that combination as one node.
So instead of having:
$$
0.01,\ 0.02
$$
we now have:
$$
0.03
$$
---
## 12. Why Combine the Smallest?
Because these are the **least probable symbols**.
They can afford to receive longer codewords.
The Huffman construction therefore pushes low-probability symbols deeper into the tree.
High-probability symbols remain closer to the root and therefore receive shorter codewords.
So the basic intuition is:
$$
\boxed{\text{High probability}\rightarrow\text{short code}}
$$
$$
\boxed{\text{Low probability}\rightarrow\text{long code}}
$$

$$
\boxed{
\frac{H(X)}{T_s}>\frac{C}{T_c}
}

then:
> It is impossible to transmit the information and reconstruct it with arbitrarily small probability of error.
The source is demanding more information rate than the channel can support.

### It does **not** give us the recipe for constructing those codes.

Huffman coding may encounter symbols with equal probabilities.

## F10. Complete Huffman algorithm
### Step 1
List all source symbols with their probabilities.
### Step 2
Arrange probabilities from smallest to largest.
### Step 3
Select the two smallest probabilities.
### Step 4
Combine them into a new node whose probability equals their sum.
### Step 5
Insert the new probability back into the list.
### Step 6
Repeat until only one node remains.
### Step 7
The resulting structure is the Huffman tree.
### Step 8
Assign `0` to one branch and `1` to the other.
### Step 9
Read the path from root to each symbol to obtain its codeword.
### Step 10
Calculate average length:
`Lavg = sum pi li`
Huffman coding produces an optimal binary prefix code for the given symbol probabilities.

# H. ARITHMETIC CODING
## H1. Principle of arithmetic coding
Arithmetic coding represents an entire sequence using **one number inside an interval between 0 and 1**.
Initially:
`[0,1)`
The interval is divided according to symbol probabilities.
When a symbol occurs, the current interval is narrowed to the subinterval corresponding to that symbol.
This continues for every symbol.
At the end, **any number inside the final interval represents the complete message**.

`A → [0,0.5)`

## H5. How does the final interval identify the complete message?
Every transmitted symbol narrows the interval.
Therefore, after all symbols have been processed, the final interval corresponds uniquely to the complete sequence.
The decoder starts with `[0,1)` and repeatedly determines which symbol's subinterval contains the encoded number.
It then reconstructs the original sequence.

## H6. Why can arithmetic coding allow fractional average rates?
Arithmetic coding encodes a **whole sequence**, rather than assigning an integer number of bits independently to each symbol.
Therefore the total number of bits needed can approach the theoretical information content of the entire sequence.
For long sequences, the average rate can approach:
`H`
even when the average information per symbol is not an integer.

## H8. Why must the probability model be available to encoder and decoder?
The encoder uses probabilities to determine how the interval is divided.
The decoder must perform exactly the same subdivisions to determine which symbols correspond to the encoded value.
If the encoder and decoder use different probability models, they will produce different intervals.
Therefore decoding will fail.
### Answer
**Both sides must use the same probability model so that they construct identical interval subdivisions.**

## H9. One advantage and one limitation
### Advantage
Arithmetic coding can achieve an average rate **very close to the source entropy**, especially for long sequences.
### Limitation
It is generally more computationally complex than simple prefix coding such as Huffman coding and requires careful numerical/range implementation.

Number of 1s in a binary word.

Number of positions where two binary words differ.

There are:
`7 total bits`
`4 data bits`
`3 parity bits`

`1,2,4`

`3,5,6,7`

The binary value of the syndrome gives the position of a single-bit error.

| Code length    | Integer number of bits                    | Fractional average rate possible         |
| Prefix code    | Yes                                       | No ordinary prefix codewords             |
| Efficiency     | Close to entropy                          | Can approach entropy more closely        |
| Complexity     | Lower                                     | Higher                                   |
| Best feature   | Simple and fast                           | Excellent compression for long sequences |
### Conclusion
Huffman coding assigns individual binary codewords according to symbol probabilities.
Arithmetic coding represents an entire sequence by progressively narrowing a numerical interval.
Both exploit source probability, but arithmetic coding can generally get closer to the theoretical entropy limit.

## I6. Self-information, entropy, conditional entropy and mutual information
## Self-information
For event x:
`I(x)=-log2 p(x)`
It measures the information associated with a particular event.
Rare events have greater self-information.
---
## Entropy
Entropy is the average self-information:
`H(X)=-sum px log2 px`
It represents the average uncertainty of a source.
---
## Conditional entropy
`H(X|Y)`
represents the uncertainty remaining in X after Y is known.
---
## Mutual information
`I(X;Y)`
measures the reduction in uncertainty about X due to knowing Y.
Mathematically:
`I(X;Y)=H(X)-H(X|Y)`
Similarly:
`I(X;Y)=H(Y)-H(Y|X)`
And:
`I(X;Y)=H(X)+H(Y)-H(X,Y)`
Conceptually:
**Entropy → total uncertainty**
**Conditional entropy → remaining uncertainty**
**Mutual information → uncertainty removed**

## I7. Complete prefix-code problem
Consider probabilities:
`0.45, 0.25, 0.20, 0.10`
## Step 1: Arrange probabilities
`0.10, 0.20, 0.25, 0.45`
## Step 2: Huffman combinations
Smallest two:
`0.10+0.20=0.30`
Remaining:
`0.25,0.30,0.45`
Next:
`0.25+0.30=0.55`
Finally:
`0.45+0.55=1`
A valid code can therefore have lengths:

| Symbol | Probability | Code | Length |
| ------ | ----------: | ---- | -----: |
| A      |        0.45 | 0    |      1 |
| B      |        0.25 | 10   |      2 |
| C      |        0.20 | 110  |      3 |
| D      |        0.10 | 111  |      3 |
## Step 3: Entropy
Self-information:
`A: -log2(0.45) ≈ 1.152`
`B: -log2(0.25)=2`
`C: -log2(0.20)≈2.322`
`D: -log2(0.10)≈3.322`
Entropy:
`H = 0.45(1.152)+0.25(2)+0.20(2.322)+0.10(3.322)`
`H ≈ 1.815 bits/symbol`
## Step 4: Average code length
`Lavg=0.45(1)+0.25(2)+0.20(3)+0.10(3)`
`=0.45+0.50+0.60+0.30`
`=1.85 bits/symbol`
## Step 5: Efficiency
`η=H/Lavg ×100`
`≈1.815/1.85 ×100`
`≈98.1%`
## Step 6: Bound check
`H <= Lavg < H+1`
`1.815 <= 1.85 < 2.815`
✓ Correct.
### Final answer
**Entropy ≈ 1.815 bits/symbol**
**Average length = 1.85 bits/symbol**
**Efficiency ≈ 98.1%**
**Redundancy ≈ 0.035 bits/symbol**
