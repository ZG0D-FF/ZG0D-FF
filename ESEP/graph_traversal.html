Graph Traversal (Data Structures & Algorithms)

What Is a Graph?

A graph is a non-linear data structure that works like a map. It is made of two main parts:

  • V (Vertices or Nodes): The specific locations or points on the map.
  • E (Edges): The lines or roads connecting two locations together.

Types of Graphs You Must Know

Common Graph Representations

  1. Adjacency Matrix: A 2D grid/array. Very fast to check if a specific road exists O(1), but it wastes a lot of memory O(V²).
  2. Adjacency List: Each location simply holds a list of its direct neighbors. It is highly memory efficient O(V+E) and is the best choice for traversals (BFS/DFS).
  3. Edge List: Just a big list of every pair of connected nodes. Compact, but very slow when you need to find a node's neighbors.

What Is Graph Traversal?

Graph traversal is the process of visiting every single location in the graph systematically, exactly once, by following the edges. It is the backbone of almost every advanced graph algorithm.

Crucial Rule: Unlike a standard tree, graphs can have loops. If you aren't careful, you will walk in circles forever.

To safely traverse a graph, algorithms must:

  • Maintain a visited marker (like an array or set) for each location to avoid infinite loops.
  • Optionally restart the search from any unvisited location to ensure disconnected islands aren't ignored.

The two fundamental strategies are:

  1. Breadth First Search (BFS): Explores like a ripple in water—level by level.
  2. Depth First Search (DFS): Explores like a maze runner—going as deep as possible down one path before hitting a dead end and turning back.

Breadth First Search (BFS)

The Idea

BFS starts at a chosen location, checks all of its direct neighbors first, then checks the neighbors of those neighbors, moving outward in layers. Because it expands equally in all directions, it is guaranteed to find the shortest path (fewest edges) in an unweighted graph.

Data Structure Used

A Queue (First-In, First-Out). As we discover new locations, we make them wait in line. This naturally forces the level-by-level effect.

Step-by-Step Algorithm

  1. Mark the start location as visited and put it in the Queue.
  2. While the Queue isn't empty:
    • Take the front item out (let's call it curr).
    • For every unvisited neighbor of curr: mark it visited immediately and put it at the back of the Queue.
  3. (For disconnected graphs): Check if any location is still unvisited, and start a fresh BFS from it.

C Code Implementation

#include <stdio.h>
#include <stdbool.h>

#define V 5 // Total number of vertices
// 🔧 TECH (Level 0): Set maximum nodes to 5.
// 💡 THINK: "We are throwing a party for a maximum of 5 people."

#define MAXQ 100 // Queue capacity limit
// 🔧 TECH (Level 0): Set queue array size to 100.
// 💡 THINK: "Our waiting room holds 100 chairs max."

// Adjacency list stored as a 2D array for simplicity:
// adj[i][0] stores the NUMBER of neighbors for vertex 'i'
// adj[i][1..] stores the actual IDs of those neighbors
// 🔧 TECH (Level 0): 2D Array where row = node, col 0 = neighbor count, col 1+ = neighbor IDs.
// 💡 THINK: "adj is our phonebook. Page 'i' says how many friends they have, and their names."
int adj[V][V + 1];

void addEdge(int u, int v) {
    // Add 'v' to 'u's list, and increase 'u's neighbor count
    // 🔧 TECH (Level 0): Increment neighbor count for node u, then save node v at that index.
    // 💡 THINK: "Write Bob's name in Alice's phonebook."
    adj[u][++adj[u][0]] = v;
    // Because this is undirected, we also add 'u' to 'v's list.
    // Remove this exact line if building a directed graph!
    // 🔧 TECH (Level 0): Do the exact reverse for node v to create a 2-way connection.
    // 💡 THINK: "Write Alice's name in Bob's phonebook too."
    adj[v][++adj[v][0]] = u; 
}

// BFS starting from a single source
int bfs(int start, int order[V]) {
    // Keep track of where we've been to avoid infinite loops
    // 🔧 TECH (Level 0): Array of booleans, initialized to false. True means we processed it.
    // 💡 THINK: "A guest list. If they are already checked off, don't invite them again."
    bool visited[V] = { false };
    
    // Setup a simple array-based Queue
    // 🔧 TECH (Level 0): 'front' tracks the dequeue index, 'rear' tracks the enqueue index.
    // 💡 THINK: "The actual waiting room line."
    int queue[MAXQ], front = 0, rear = 0, count = 0;
    
    // 1. Mark the starting node and put it in the queue
    // 🔧 TECH (Level 0): Mark start true, store in queue[rear], then increment rear.
    // 💡 THINK: "Check off the host on the guest list and put them at the front of the line."
    visited[start] = true;
    queue[rear++] = start;
    
    // 2. Keep processing as long as people are in the queue
    // 🔧 TECH (Level 0): Loop runs until front index catches up to rear index.
    // 💡 THINK: "As long as the waiting room isn't empty..."
    while (front < rear) {
        int u = queue[front++]; // Pull the first person out
        // 🔧 TECH (Level 0): Read queue[front], then increment front.
        // 💡 THINK: "Call the next person from the front of the line."
        
        order[count++] = u;     // Record our traversal
        
        // 3. Look at all the neighbors of 'u'
        // 🔧 TECH (Level 0): Loop from 1 to the neighbor count (stored at index 0).
        // 💡 THINK: "Open this person's phonebook and look at all their friends."
        for (int i = 1; i <= adj[u][0]; i++) {
            int v = adj[u][i];
            
            // If we haven't visited this neighbor yet...
            // 🔧 TECH (Level 0): If visited[v] is false...
            // 💡 THINK: "Is this friend missing from the guest list?"
            if (!visited[v]) {
                // Mark it visited IMMEDIATELY and add to the queue
                // 🔧 TECH (Level 0): Set visited[v] to true, push to queue, increment rear.
                // 💡 THINK: "Check them off the guest list NOW, and send them to the back of the waiting room."
                visited[v] = true;
                queue[rear++] = v;
            }
        }
    }
    return count;
}

// BFS that checks for disconnected "islands"
// 🔧 TECH (Level 0): Handles graphs where some nodes are completely disconnected.
// 💡 THINK: "What if there are two completely separate groups of friends who don't know each other?"
int bfsAllComponents(int order[V]) {
    bool visited[V] = { false };
    int queue[MAXQ], count = 0;
    
    // Loop over every single vertex in the entire graph
    // 🔧 TECH (Level 0): Iterate through all nodes 0 to V-1.
    // 💡 THINK: "Look at every single person in the whole city."
    for (int s = 0; s < V; s++) {
        // If it was visited by a previous island's BFS, ignore it
        // 🔧 TECH (Level 0): If visited[s] is true, skip to next iteration.
        // 💡 THINK: "Did they already attend a party? Skip them."
        if (visited[s]) continue;
        
        // We found an unvisited island! Start a fresh BFS here.
        // 🔧 TECH (Level 0): Reset queue pointers, mark s as visited, push to queue.
        // 💡 THINK: "Found someone who hasn't partied! Start a totally new party with them as the host."
        int front = 0, rear = 0;
        visited[s] = true;
        queue[rear++] = s;
        
        while (front < rear) {
            int u = queue[front++];
            order[count++] = u;
            for (int i = 1; i <= adj[u][0]; i++) {
                int v = adj[u][i];
                if (!visited[v]) {
                    visited[v] = true;
                    queue[rear++] = v;
                }
            }
        }
    }
    return count;
}

Super-Simple BFS in Python (The Easiest to Read)

Python makes BFS extremely clean because we don't have to manually manage array sizes, and dictionaries act as perfect phonebooks.

def bfs(graph, start):
    # 🔧 TECH (Level 0): Create an empty set to track visited nodes.
    # 💡 THINK: "Our guest list is an empty set (no duplicates allowed)"
    visited = set()
    # 🔧 TECH (Level 0): Initialize a list acting as a queue, containing the start node.
    # 💡 THINK: "Our waiting line starts with just the host"
    queue = [start]
    
    # 🔧 TECH (Level 0): Add the start node to the visited set.
    # 💡 THINK: "Mark host as invited"
    visited.add(start)
    
    while queue:
        # 🔧 TECH (Level 0): Remove and return the first element (index 0) from the list.
        # 💡 THINK: "Call the first person in line"
        current = queue.pop(0)
        print(f"Visiting: {current}")
        
        # 🔧 TECH (Level 0): Iterate through all nodes connected to 'current' in the dictionary.
        # 💡 THINK: "Look at all their friends in the phonebook"
        for neighbor in graph[current]:
            if neighbor not in visited:
                # 🔧 TECH (Level 0): Add the neighbor to visited set and append to end of queue.
                # 💡 THINK: "Invite them and put them at the end of the line"
                visited.add(neighbor)
                queue.append(neighbor)

Key BFS Uses

  • Shortest path in unweighted graphs (e.g., GPS shortest-hop).
  • Level-order processing (e.g., finding the nearest '1' in a grid).
  • Social network "degrees of separation".

Depth First Search (DFS)

The Idea

DFS goes as deep as possible along a single path before turning back. It dives into a neighbor, then that neighbor's neighbor, and only turns around ("backtracks") when it hits a dead end where all neighbors are already visited.

Data Structure Used

A Stack (Last-In, First-Out). You can use an explicit stack variable, or simply rely on Recursion (which uses the computer's built-in call stack automatically).

Step-by-Step Algorithm (Recursive)

  1. Mark the current location as visited.
  2. Look at every neighbor. If it's unvisited, recursively call DFS on it immediately.
  3. When you run out of unvisited neighbors, the function naturally returns (backtracks) to the previous step.

C Code Implementation

// Recursive DFS Helper
// 🔧 TECH (Level 0): A function that calls itself to go deeper.
void dfsRec(int u, bool visited[V], int order[V], int *count) {
    // Mark current spot as visited the moment we land on it
    // 🔧 TECH (Level 0): Set visited[u] to true, store u in order array, increment count.
    // 💡 THINK: "We stepped into this room of the maze. Leave a breadcrumb."
    visited[u] = true;
    order[(*count)++] = u;
    
    // Check all neighbors
    // 🔧 TECH (Level 0): Loop through all neighbors of u (from 1 to neighbor count).
    // 💡 THINK: "Look at all the doors leading out of this room."
    for (int i = 1; i <= adj[u][0]; i++) {
        int v = adj[u][i];
        if (!visited[v]) {
            // If unvisited, dive in immediately! (This pauses the current loop)
            // 🔧 TECH (Level 0): Recursively call dfsRec for neighbor v.
            // 💡 THINK: "Run through the first open door immediately! We will check the other doors when we hit a dead end and come back."
            dfsRec(v, visited, order, count);
        }
    }
}

// DFS that handles disconnected islands
// 🔧 TECH (Level 0): Outer loop to ensure all nodes are processed.
// 💡 THINK: "What if there are completely separate mazes on the map?"
int dfsAllComponents(int order[V]) {
    bool visited[V] = { false };
    int count = 0;
    
    // Check every node to make sure no islands are left behind
    // 🔧 TECH (Level 0): Loop through nodes 0 to V-1.
    // 💡 THINK: "Check the entrance of every known maze."
    for (int s = 0; s < V; s++) {
        if (!visited[s]) {
            // 🔧 TECH (Level 0): If false, start a new recursive DFS tree here.
            // 💡 THINK: "Found an unexplored maze! Dive in."
            dfsRec(s, visited, order, &count);
        }
    }
    return count;
}

// Iterative DFS using our own explicit Stack (No Recursion)
// 🔧 TECH (Level 0): Uses an array as a LIFO Stack instead of the call stack.
int dfsIterative(int start, int order[V]) {
    bool visited[V] = { false };
    int stack[MAXS], top = -1, count = 0;
    
    // Push the starting node onto the stack
    // 🔧 TECH (Level 0): Increment 'top' index and store start value.
    // 💡 THINK: "Write the starting room down on our clipboard."
    stack[++top] = start;
    
    while (top >= 0) {
        // Pop the most recently added item off the stack (LIFO)
        // 🔧 TECH (Level 0): Read stack[top] and decrement 'top'.
        // 💡 THINK: "Look at the MOST RECENT room we wrote on the clipboard."
        int u = stack[top--];
        
        // In iterative DFS, a node might sit on the stack and get visited 
        // by a different path before we pop it. So we check here:
        // 🔧 TECH (Level 0): Skip if already visited.
        // 💡 THINK: "Did we already visit this room through another hallway? If yes, skip."
        if (visited[u]) continue;
        
        visited[u] = true;
        order[count++] = u;
        
        // Push neighbors onto stack in REVERSE order. 
        // This ensures we pop/visit the first neighbor first, mimicking recursion.
        // 🔧 TECH (Level 0): Loop backwards from neighbor count down to 1. Push unvisited neighbors to stack.
        // 💡 THINK: "Write all unvisited neighbor rooms onto the clipboard. Write them backwards so the FIRST door is at the top of our list to check next."
        for (int i = adj[u][0]; i >= 1; i--) {
            int v = adj[u][i];
            if (!visited[v]) {
                stack[++top] = v;
            }
        }
    }
    return count;
}

Handling Special Cases

Real-world graphs are rarely perfectly connected, unweighted, two-way streets. Here is how standard BFS/DFS breaks, and how we fix it.

1. Disconnected Graphs

The Scenario: Your map has two completely separate cities with no roads connecting them.

Why does standard BFS/DFS fail? If you start BFS in City A, the queue will empty once City A is fully explored. City B is left completely undiscovered.

How to fix it? Wrap your entire traversal in a loop that checks the "guest list" (visited array) for every single person in the whole world. If you find an uninvited person, start a brand new BFS/DFS right there!

💡 THINK: "Check every house in the world. If you find an unexplored island, start a new party there."

for node in range(total_nodes):
    if node not in visited:
        # Found a new island! Start a new traversal here.
        bfs(graph, node)

2. Directed Graphs (One-Way Streets)

The Scenario: The edges have arrows (A → B). You can go from A to B, but NOT from B to A.

Why does standard Cycle Detection fail? In a normal undirected graph, if you see an already-visited node, you found a loop. But in a Directed graph, seeing a visited node just means two different one-way paths led to the same dead end. That's not a cycle!

How to fix it? You need a second tracker called in_stack. A cycle ONLY exists if you run into a node that is currently in your active, unfinished recursive dive.

💡 THINK: "Imagine dropping glowing breadcrumbs as you walk deep into a maze, and picking them up as you walk backward out of dead ends. A loop only happens if you step on a breadcrumb that is STILL glowing on the floor!"

def has_cycle_dfs(node, visited, in_stack):
    visited.add(node)
    in_stack.add(node) # Drop breadcrumb
    
    for neighbor in graph[node]:
        if neighbor in in_stack:
            return True # Stepped on an active breadcrumb! LOOP!
        if neighbor not in visited:
            if has_cycle_dfs(neighbor, visited, in_stack):
                return True
                
    in_stack.remove(node) # Pick up breadcrumb as we back out of dead end
    return False

3. Weighted Graphs

The Scenario: Roads have different costs. Highway A→B takes 1 hour, but backroad A→C takes 4 hours.

Why does standard BFS fail? Standard BFS assumes every road takes 1 hour. It expands evenly in all directions by counting the "number of edges", totally ignoring the actual road costs.

How to fix it? Swap the standard Queue (FIFO) for a Priority Queue (Min-Heap). This forces the algorithm to always process the "cheapest known" location first, rather than just the "next in line".

💡 THINK: "Instead of standing in a normal waiting line, everyone in line is automatically sorted by how cheap their ticket was. The cheapest ticket ALWAYS goes first."

ConditionSolution Algorithm
All costs are positive (Normal driving)Dijkstra's Algorithm (Uses Priority Queue)
Some costs are negative (You gain money!)Bellman-Ford (Dijkstra breaks on negative paths)

Multi-Source BFS

Instead of starting at one single point, what if we have multiple starting points? We simply push all sources into our Queue at the very beginning (at distance 0). The BFS still expands outward properly, automatically calculating the shortest distance to the nearest source for every vertex simultaneously.

Classic Problem: "Rotten Oranges" (finding how long it takes for rot to spread from multiple bad oranges).

int minutesToRotAll() {
    // Set up our queue arrays (one for Row, one for Column)
    // 🔧 TECH (Level 0): Two arrays to hold coordinates.
    // 💡 THINK: "A waiting list for zombies. One list for their X coordinate, one for Y."
    int qr[N * M], qc[N * M], front = 0, rear = 0;
    int dist[N][M];
    memset(dist, -1, sizeof(dist));
    int freshCount = 0;
    
    // 1. Multi-Source Setup: Push ALL initially rotten oranges into the Queue
    // 🔧 TECH (Level 0): Nested loops scan the entire grid to find all '2's (sources).
    // 💡 THINK: "Scan the city. Find EVERY Patient Zero and put them in the queue at Time = 0."
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < M; j++) {
            if (grid[i][j] == 2) { // If rotten
                qr[rear] = i; qc[rear] = j; rear++;
                dist[i][j] = 0;
            } else if (grid[i][j] == 1) {
                // 🔧 TECH (Level 0): Count 1s to verify all are processed later.
                // 💡 THINK: "Count the uninfected humans so we know when everyone is a zombie."
                freshCount++; 
            }
        }
    }
    
    int maxTime = 0;
    
    // 2. Standard BFS loop
    // 🔧 TECH (Level 0): Standard while loop using front and rear pointers.
    // 💡 THINK: "Release the zombies one by one from the waiting line."
    while (front < rear) {
        int r = qr[front], c = qc[front];
        front++;
        
        // Check all 4 directions (Up, Down, Left, Right)
        // 🔧 TECH (Level 0): Iterate through coordinate offsets.
        // 💡 THINK: "The zombie reaches its arms out North, South, East, and West."
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            
            // If inside grid AND it's a fresh orange AND unvisited...
            // 🔧 TECH (Level 0): Bounds check, target value check, and dist check (-1).
            // 💡 THINK: "Did they grab a human? Or just a wall?"
            if (nr >= 0 && nr < N && nc >= 0 && nc < M && 
                grid[nr][nc] == 1 && dist[nr][nc] == -1) {
                
                // Rot it! Time taken is current orange's time + 1 minute
                // 🔧 TECH (Level 0): Update target distance to current distance + 1.
                // 💡 THINK: "Human is bitten! They become a zombie in exactly 1 minute."
                dist[nr][nc] = dist[r][c] + 1;
                if (dist[nr][nc] > maxTime) maxTime = dist[nr][nc];
                
                freshCount--; // One less fresh orange
                
                // Add the newly rotten orange to the queue to infect others
                // 🔧 TECH (Level 0): Push new coordinates to queue arrays.
                // 💡 THINK: "Send the newly turned zombie to the back of the waiting line to bite more people."
                qr[rear] = nr; qc[rear] = nc; rear++;
            }
        }
    }
    
    // If fresh oranges remain that we couldn't reach, return -1. Otherwise, return time.
    // 🔧 TECH (Level 0): Ternary operator checks if freshCount is 0.
    // 💡 THINK: "Did any humans survive in an isolated bunker? If yes, return -1."
    return (freshCount == 0) ? maxTime : -1; 
}

    fresh_count = 0
    
    # 🔧 TECH (Level 0): Multi-Source Setup - Iterate over every cell in grid.
    # 💡 THINK: "Send a scout to look at every single building in the city."
    for r in range(rows):
        for c in range(cols):
            # 🔧 TECH (Level 0): If value is 2, append to queue with time=0.
            # 💡 THINK: "If building has a Patient Zero, put them in line immediately at minute 0."
            # ❓ WHY 2?: In the classic 'Rotten Oranges' problem, the grid uses specific numbers: 0 = Empty, 1 = Fresh Orange (Human), 2 = Rotten Orange (Zombie). We are specifically hunting for the rotten ones here.
            if grid[r][c] == 2:
                queue.append((r, c, 0)) # (row, col, minutes)
                
            # 🔧 TECH (Level 0): If value is 1, increment fresh counter.
            # 💡 THINK: "If building has humans, add to our tally."
            elif grid[r][c] == 1:
                fresh_count += 1
                
    # 🔧 TECH (Level 0): Initialize max time tracker.
    # 💡 THINK: "Start the master stopwatch at 0."
    max_time = 0
    
    # 🔧 TECH (Level 0): Define neighbor offsets (down, up, right, left).
    # 💡 THINK: "Define the 4 directions a zombie can lunge."
    directions = [(1,0), (-1,0), (0,1), (0,-1)]
    
    # 🔧 TECH (Level 0): Standard BFS loop continues until queue is empty.
    # 💡 THINK: "Unleash the horde! Keep going until the waiting line is empty."
    while queue:
        # 🔧 TECH (Level 0): Pop tuple from left side of deque.
        # 💡 THINK: "Call the next zombie from the front of the line."
        # ❓ WHAT IS popleft()?: A standard Python list (array) is slow if you pull from the front, because it has to shift every other item over. A `deque` (Double Ended Queue) is a special tube where pulling from the front (`popleft()`) is instantly fast!
        r, c, minutes = queue.popleft()
        
        # 🔧 TECH (Level 0): Update max_time if current minutes is higher.
        # 💡 THINK: "Update the master stopwatch to match this zombie's infection time."
        max_time = max(max_time, minutes)
        
        # 🔧 TECH (Level 0): Loop through the 4 directional offsets.
        # 💡 THINK: "Zombie lunges in all 4 directions."
        for dr, dc in directions:
            # 🔧 TECH (Level 0): Calculate neighbor coordinates.
            # 💡 THINK: "Target the building next door."
            # ❓ WHY r + dr?: `r` and `c` are the current zombie's location (e.g., Row 5, Col 5). `dr` and `dc` are the direction offsets (e.g., Row +1, Col 0 is moving South). Adding them together gives the exact coordinates of the building next door (Row 6, Col 5)!
            nr, nc = r + dr, c + dc
            
            # 🔧 TECH (Level 0): Check if coordinates are in bounds AND cell equals 1.
            # 💡 THINK: "Did they grab a human? Or just hit a wall?"
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                # 🔧 TECH (Level 0): Change value to 2, decrement counter.
                # 💡 THINK: "Human is bitten! Cross them off the uninfected tally."
                grid[nr][nc] = 2
                fresh_count -= 1
                
                # 🔧 TECH (Level 0): Append new coordinates to queue, incrementing time by 1.
                # 💡 THINK: "Send the new zombie to the back of the line. Their time is exactly 1 minute later."
                queue.append((nr, nc, minutes + 1))
                
    # 🔧 TECH (Level 0): Return max_time if fresh_count is 0, else return -1.
    # 💡 THINK: "If there are zero humans left, stop the watch. Otherwise, someone survived in a bunker (-1)."
    return max_time if fresh_count == 0 else -1

Topological Sorting

Topological sorting creates a linear timeline for Directed Acyclic Graphs (DAG). If a task 'A' must happen before task 'B' (A → B), topological sort guarantees 'A' will appear before 'B' in the final list.

Real world analogy: Figuring out the exact order to take university courses based on their prerequisites.

Method 1: Kahn's Algorithm (BFS-Based)

This counts how many prerequisites every node has (its "in-degree"). Nodes with 0 prerequisites go in the queue. When processed, they "complete", reducing the prerequisites of their neighbors.

void topoSortKahn() {
    // 🔧 TECH (Level 0): Initialize array of size V with all 0s.
    // 💡 THINK: "Create a list to track how many prerequisites every course has."
    int inDegree[V] = {0};
    
    // 1. Calculate how many incoming arrows (prerequisites) each node has
    // 🔧 TECH (Level 0): Loop through every node 'u', then loop through its neighbors 'i'.
    // 💡 THINK: "Check every course. Look at all the advanced courses it unlocks."
    for (int u = 0; u < V; u++)
        for (int i = 1; i <= adj[u][0]; i++)
            // 🔧 TECH (Level 0): Increment the inDegree counter for the target neighbor node.
            // 💡 THINK: "Tell that advanced course: 'You have one more prerequisite to finish first!'"
            // ❓ WHY inDegree[adj[u][i]]++?: `adj[u][i]` gives us the ID of the neighbor. We are using that ID as an index in the `inDegree` array to count up by 1. We are basically saying "whoever is at the tip of this arrow gets +1 incoming arrows".
            inDegree[adj[u][i]]++;
            
    // 🔧 TECH (Level 0): Initialize queue array and pointers.
    // 💡 THINK: "Create a waiting line for courses we are allowed to take right now."
    int queue[V], front = 0, rear = 0;
    
    // 2. Put nodes with ZERO prerequisites into the queue to start
    // 🔧 TECH (Level 0): Loop over nodes, if inDegree is 0, add to queue.
    // 💡 THINK: "Find all the 101-level freshman courses that have NO prerequisites, and put them in the line."
    for (int u = 0; u < V; u++)
        if (inDegree[u] == 0)
            queue[rear++] = u;
            
    // 🔧 TECH (Level 0): Array to hold final answer, and count of processed nodes.
    // 💡 THINK: "Our final graduation transcript."
    int order[V], count = 0;
    
    // 3. Process the queue
    // 🔧 TECH (Level 0): Standard BFS loop while queue has items.
    // 💡 THINK: "Take courses one by one from the allowed list."
    while (front < rear) {
        // 🔧 TECH (Level 0): Pop node from queue and add to 'order' array.
        // 💡 THINK: "Take the course, and write it down on our final transcript."
        int u = queue[front++];
        order[count++] = u;
        
        // We completed 'u'. Now reduce the prerequisite count for all its neighbors.
        // 🔧 TECH (Level 0): Loop through all neighbors of the popped node.
        // 💡 THINK: "Look at all the advanced courses this course unlocks."
        for (int i = 1; i <= adj[u][0]; i++) {
            int v = adj[u][i];
            
            // If a neighbor's prerequisite count drops to 0, it's ready to go in the queue!
            // 🔧 TECH (Level 0): Decrement inDegree[v] BEFORE checking if it equals 0.
            // 💡 THINK: "Cross this prerequisite off the list for the advanced course. Are there zero left?"
            // ❓ WHAT IS --inDegree[v]?: The `--` before the variable means "subtract 1 FIRST, then look at the new value". So we subtract 1 prerequisite, and if the new total is exactly 0, it means all prerequisites are finally met!
            if (--inDegree[v] == 0)
                // 🔧 TECH (Level 0): Add neighbor to queue.
                // 💡 THINK: "Yes! All prerequisites met. Put this advanced course in the 'allowed to take' line."
                queue[rear++] = v;
        }
    }
    
    // Cycle check! If we couldn't process all V vertices, a loop exists.
    // 🔧 TECH (Level 0): Compare nodes processed vs total nodes.
    // 💡 THINK: "Did we graduate? Or are we stuck because Course A requires B, and B requires A?"
    // ❓ WHY count != V?: If there is a loop (A requires B, B requires A), their prerequisite counts will NEVER reach 0. They will never enter the queue, so they never get added to our `count`. If `count` is less than `V` (total courses), a cycle trapped us!
    if (count != V) {
        printf("Graph has a cycle — topological sort not possible\n");
        return;
    }
}

from collections import deque, defaultdict

def topoSortKahn(num_nodes, edges):

    graph = defaultdict(list)

    for u, v in edges:
        graph[u].append(v)
        in_degree[v] += 1

    # 💡 THINK: "Find all the 101-level freshman courses with zero prerequisites."
    # ❓ WHAT IS IN-DEGREE?: "In-degree" literally means "how many arrows are pointing IN to this node". In our analogy, it means "how many prerequisites does this course have". So `in_degree == 0` means zero prerequisites!
    queue = deque([i for i in range(num_nodes) if in_degree[i] == 0])
    
    # 🔧 TECH (Level 0): Array to hold the final sorted result.
    # 💡 THINK: "Our final graduation transcript."
    transcript = []
    
    # 🔧 TECH (Level 0): Process queue until empty.
    # 💡 THINK: "Take courses one by one."
    while queue:
        # 🔧 TECH (Level 0): Pop node and add to result list.
        # 💡 THINK: "Take the course, write it on transcript."
        current = queue.popleft()
        transcript.append(current)
        
        # 🔧 TECH (Level 0): Loop through neighbors.
        # 💡 THINK: "Look at the advanced courses this unlocks."
        for neighbor in graph[current]:
            # 🔧 TECH (Level 0): Decrement neighbor's in-degree.
            # 💡 THINK: "Cross this prerequisite off the advanced course's list."
            # ❓ WHY -= 1?: We just finished taking `current` (the basic course). Therefore, all the advanced courses that relied on it just lost one of their prerequisites. We subtract 1 to represent that!
            in_degree[neighbor] -= 1
            
            # 🔧 TECH (Level 0): If in-degree hits 0, append to queue.
            # 💡 THINK: "If zero prerequisites left, we are finally allowed to take it!"
            if in_degree[neighbor] == 0:
                queue.append(neighbor)
                
    # 🔧 TECH (Level 0): Check if result length matches total nodes.
    # 💡 THINK: "Did we take all courses, or did a cycle trap us?"
    if len(transcript) == num_nodes:
        return transcript
    else:
        return [] # Cycle detected!

Shortest Path Algorithms (Weighted)

When roads have different lengths/costs, plain BFS doesn't work. We need tools that respect the edge weights.

1. Dijkstra's Algorithm

Finds the shortest path from a single source. It uses a Priority Queue (or array) to always expand the currently known "closest" unvisited node first. Limitation: Fails entirely if the graph contains negative road weights.

// Dijkstra using an Adjacency Matrix and simple Array
void dijkstra(int src) {
    // 🔧 TECH (Level 0): Arrays to track shortest known distance and visit status.
    // 💡 THINK: "A notepad tracking the fastest driving time to every city, and a checklist of cities we've fully explored."
    int dist[V];
    bool visited[V] = { false };
    
    // 🔧 TECH (Level 0): Initialize all distances to infinity.
    // 💡 THINK: "Assume every city is impossibly far away until we discover a road to it."
    for (int i = 0; i < V; i++) dist[i] = INF;
    
    // 🔧 TECH (Level 0): Distance to source is 0.
    // 💡 THINK: "The driving time to your own driveway is 0 minutes."
    dist[src] = 0; 
    
    // 🔧 TECH (Level 0): Loop V-1 times to process all vertices.
    // 💡 THINK: "Explore the map, city by city."
    for (int count = 0; count < V - 1; count++) {
        // 🔧 TECH (Level 0): Find unvisited vertex with minimum distance.
        // 💡 THINK: "Look at our notepad. Which unvisited city currently has the shortest driving time? Let's go there next."
        // ❓ WHY minDistanceVertex?: We always expand the closest node first (greedy). This guarantees that once we 'visit' a node, we have absolutely found the shortest possible path to it.
        int u = minDistanceVertex(dist, visited);
        if (u == -1) break; 
        
        // 🔧 TECH (Level 0): Mark vertex as visited.
        // 💡 THINK: "Mark this city off our checklist. We've explored it."
        visited[u] = true;
        
        // 🔧 TECH (Level 0): Iterate through all V vertices to find neighbors.
        // 💡 THINK: "Look at all the roads leaving this city."
        for (int v = 0; v < V; v++) {
            // 🔧 TECH (Level 0): If unvisited, edge exists, u is reachable, and path via u is strictly less than current dist[v]...
            // 💡 THINK: "Does this road lead to an unvisited city? And is taking this road FASTER than the old route we had written down?"
            // ❓ WHAT IS dist[u] + graph[u][v] < dist[v]?: `dist[u]` is time to get here. `graph[u][v]` is time to drive the road to neighbor `v`. If their sum is less than `dist[v]` (the old record), we found a shortcut!
            if (!visited[v] && graph[u][v] != 0 && 
                dist[u] != INF && dist[u] + graph[u][v] < dist[v]) {
                
                // 🔧 TECH (Level 0): Update dist[v] with the new shorter distance.
                // 💡 THINK: "Erase the old time on our notepad and write down the new faster shortcut!"
                dist[v] = dist[u] + graph[u][v];
            }
        }
    }
}

Super-Simple Dijkstra in Python (using Priority Queue)

Instead of scanning arrays like C, Python uses heapq (a priority queue) to instantly hand us the closest city.

import heapq

def dijkstra(graph, start):
    # 🔧 TECH (Level 0): Dictionary to hold shortest distances, default infinity.
    # 💡 THINK: "Notepad for driving times."
    distances = {node: float('infinity') for node in graph}
    distances[start] = 0
    
    # 🔧 TECH (Level 0): Priority Queue storing tuples (distance, node).
    # 💡 THINK: "A magical sorting hat that always gives us the closest city instantly."
    pq = [(0, start)]
    
    while pq:
        # 🔧 TECH (Level 0): Pop node with lowest distance.
        # 💡 THINK: "Grab the closest unexplored city."
        current_dist, current_node = heapq.heappop(pq)
        
        # 🔧 TECH (Level 0): Optimization - skip if we already found a shorter path earlier.
        # 💡 THINK: "If our notepad already has a faster time than this old record, ignore it."
        if current_dist > distances[current_node]:
            continue
            
        # 🔧 TECH (Level 0): Loop through neighbors and edge weights.
        # 💡 THINK: "Check all roads leaving this city."
        for neighbor, weight in graph[current_node].items():
            # 🔧 TECH (Level 0): Calculate total distance to neighbor.
            # 💡 THINK: "Calculate total driving time if we take this road."
            distance = current_dist + weight
            
            # 🔧 TECH (Level 0): If calculated distance is less than known distance, update and push.
            # 💡 THINK: "Is this a shortcut? If yes, update notepad and put neighbor in the sorting hat!"
            if distance < distances[neighbor]:
                distances[neighbor] = distance
                heapq.heappush(pq, (distance, neighbor))
                
    return distances

        

        
2. Bellman-Ford

        
Slower than Dijkstra, but it handles negative edge weights. It simply iterates over every single edge V-1 times to ensure distances are finalized. If it loops a final time and a distance still improves, it successfully detects a "negative-weight cycle".


// Bellman-Ford using an Edge List (u, v, weight)
void bellmanFord(int src) {
    int dist[V];
    // 🔧 TECH (Level 0): Initialize all distances to infinity.
    // 💡 THINK: "Assume every city is infinitely far away."
    for (int i = 0; i < V; i++) dist[i] = INF;
    dist[src] = 0;
    
    // 🔧 TECH (Level 0): Relax all edges V-1 times.
    // 💡 THINK: "Broadcast the shortest paths across the whole map, repeating until it ripples to the furthest city."
    // ❓ WHY V-1?: The longest possible shortest path without a cycle can only have V-1 edges. So V-1 full sweeps guarantees every city gets the memo.
    for (int i = 1; i <= V - 1; i++) {
        for (int j = 0; j < E; j++) {
            int u = edges[j].u, v = edges[j].v, weight = edges[j].weight;
            // 🔧 TECH (Level 0): If taking this edge is strictly better, update dist[v].
            // 💡 THINK: "If this road provides a shortcut, write down the new faster time."
            if (dist[u] != INF && dist[u] + weight < dist[v])
                dist[v] = dist[u] + weight;
        }
    }
    
    // 🔧 TECH (Level 0): 1 final sweep to detect negative-weight cycles.
    // 💡 THINK: "Do one last check. Did any route get EVEN SHORTER?"
    // ❓ WHY?: After V-1 sweeps, all paths SHOULD be final. If a path still gets shorter on the Vth sweep, we must be trapped in a time-traveling (negative) loop!
    for (int j = 0; j < E; j++) {
        int u = edges[j].u, v = edges[j].v, weight = edges[j].weight;
        if (dist[u] != INF && dist[u] + weight < dist[v]) {
            printf("Graph contains negative weight cycle\n");
            return;
        }
    }
}

3. Floyd-Warshall

        
Finds the shortest path between every single pair of nodes in the graph using Dynamic Programming. Very simple code (three nested loops), but very slow O(V³). Best for small, dense graphs.


void floydWarshall(int graph[V][V]) {
    int dist[V][V];
    
    // 🔧 TECH (Level 0): Copy input graph to distance matrix.
    // 💡 THINK: "Copy the original map to our notepad."
    for (int i = 0; i < V; i++)
        for (int j = 0; j < V; j++)
            dist[i][j] = graph[i][j];
            
    // 🔧 TECH (Level 0): 'k' is the intermediate vertex. Must be the OUTER loop!
    // 💡 THINK: "Test every city as a potential 'middle-man' stopover."
    // ❓ WHY outer loop?: If we don't fix 'k' first, we might find a path through 'k', but later overwrite it when testing a different path. Keeping 'k' outside ensures we build up longer paths step-by-step.
    for (int k = 0; k < V; k++) {
        // 🔧 TECH (Level 0): 'i' is the source vertex.
        // 💡 THINK: "Starting city."
        for (int i = 0; i < V; i++) {
            // 🔧 TECH (Level 0): 'j' is the destination vertex.
            // 💡 THINK: "Destination city."
            for (int j = 0; j < V; j++) {
                // 🔧 TECH (Level 0): If path through 'k' is shorter, update dist[i][j].
                // 💡 THINK: "Is driving from i ➔ k ➔ j faster than driving directly from i ➔ j?"
                if (dist[i][k] != INF && dist[k][j] != INF && 
                    dist[i][k] + dist[k][j] < dist[i][j]) {
                    dist[i][j] = dist[i][k] + dist[k][j];
                }
            }
        }
    }
}

A Minimum Spanning Tree connects every node in the graph together without any loops, using the absolute lowest total edge cost. (Used for laying cheap fiber-optic cables to all houses in a town).


        
Disjoint Set Union (DSU / Union-Find)

        
A data structure used to track which nodes are clustered together. Used by Kruskal's algorithm to ensure we don't accidentally create loops.


// Path Compression: Flattens the tree so future lookups are instant O(1)

int find(int x) {
    // 🔧 TECH (Level 0): Base case check: if node is not its own parent, recursively call find.
    // 💡 THINK: "Who is the ultimate boss of this cluster? If it's not me, ask my manager."
    if (parent[x] != x)
        // 🔧 TECH (Level 0): Set parent to the result of the recursive find (Path Compression).
        // 💡 THINK: "Once I find the ultimate boss, I'll rewrite my own record so next time I can just call the boss directly instead of asking my manager!"
        // ❓ WHY parent[x] = ?: This is 'Path Compression'. By pointing directly to the root, we flatten the tree. Next time we call find(x), it takes O(1) time instead of walking up the whole chain.
        parent[x] = find(parent[x]); 
    return parent[x];
}

// Union by Rank: Always attach the smaller tree UNDER the bigger tree's root
void unionSets(int x, int y) {
    // 🔧 TECH (Level 0): Find roots for both elements.
    // 💡 THINK: "Find the ultimate bosses for both people."
    int rootX = find(x);
    int rootY = find(y);
    
    // 🔧 TECH (Level 0): If roots are the same, they are in the same set.
    // 💡 THINK: "If they have the same boss, they are already in the same company. Do nothing."
    if (rootX == rootY) return;
    
    // 🔧 TECH (Level 0): Attach smaller rank tree under larger rank tree.
    // 💡 THINK: "The smaller company gets bought out by the bigger company. The smaller boss now reports to the bigger boss."
    if (rank_[rootX] < rank_[rootY]) {
        parent[rootX] = rootY;
    } else if (rank_[rootX] > rank_[rootY]) {
        parent[rootY] = rootX;
    } else {
        // 🔧 TECH (Level 0): If ranks are equal, pick one as root and increment its rank.
        // 💡 THINK: "If companies are the same size, pick one boss to be the CEO, and promote them."
        parent[rootY] = rootX;
        rank_[rootX]++;
    }
}



        

        
Kruskal's Algorithm (Edge-Based)

        
Sort all edges from cheapest to most expensive. Keep adding the cheapest edge to your MST, as long as it doesn't create a loop (checked instantly via DSU). Best for sparse graphs.


// Kruskal's MST (Requires the DSU 'find' and 'unionSets' functions from above)
int kruskalMST(Edge edges[], int E) {

    // 💡 THINK: "Sort the catalog of cables from cheapest to most expensive."
    qsort(edges, E, sizeof(Edge), compareEdges);
    
    int mstWeight = 0;
    
    // 🔧 TECH (Level 0): Loop through sorted edges.
    // 💡 THINK: "Look at the cheapest available cable."
    for (int i = 0; i < E; i++) {
        int u = edges[i].u;
        int v = edges[i].v;
        
        // 🔧 TECH (Level 0): Use DSU to check if they are in the same set.
        // 💡 THINK: "Are these two houses already connected to the same grid?"
        if (find(u) != find(v)) {
            // 🔧 TECH (Level 0): Union them and add weight.
            // 💡 THINK: "No? Then buy this cheap cable and connect them!"
            unionSets(u, v);
            mstWeight += edges[i].weight;
        }
    }
    return mstWeight;
}



        
Super-Simple Kruskal's in Python


class DSU:
    def __init__(self, n):
        self.parent = list(range(n))
    
    def find(self, i):
        if self.parent[i] != i:
            self.parent[i] = self.find(self.parent[i])
        return self.parent[i]
        
    def union(self, i, j):
        root_i = self.find(i)
        root_j = self.find(j)
        if root_i != root_j:
            self.parent[root_i] = root_j
            return True
        return False

def kruskals(num_nodes, edges):
    # 🔧 TECH (Level 0): Sort edges by weight (the 3rd element).
    # 💡 THINK: "Sort catalog cheapest to most expensive."
    edges.sort(key=lambda x: x[2])
    
    dsu = DSU(num_nodes)
    mst_weight = 0
    
    for u, v, weight in edges:
        # 🔧 TECH (Level 0): Union returns True if they were separate.
        # 💡 THINK: "If they aren't already connected, buy the cable!"
        if dsu.union(u, v):
            mst_weight += weight
            
    return mst_weight



        

        
Prim's Algorithm (Vertex-Based)

        
Start at one node. Continuously pick the cheapest road that connects your growing tree to an outsider node. Almost identical structure to Dijkstra. Best for dense graphs.


// Prim's MST using Adjacency Matrix
void primMST(int graph[V][V]) {
    int parent[V]; // Array to store the constructed MST
    int key[V];    // Minimum weight edge to pick this node
    bool inMST[V] = { false };
    
    // 🔧 TECH (Level 0): Initialize all keys to infinity.
    // 💡 THINK: "Every house is currently infinitely expensive to connect to our grid."
    for (int i = 0; i < V; i++) key[i] = INF;
    
    // 🔧 TECH (Level 0): Start at node 0.
    // 💡 THINK: "Build the power plant at House 0. Cost to connect it to itself is 0."
    key[0] = 0;
    parent[0] = -1; // Root of MST
    
    // 🔧 TECH (Level 0): Loop V-1 times to add all other vertices.
    // 💡 THINK: "Connect the remaining houses one by one."
    for (int count = 0; count < V - 1; count++) {
        // 🔧 TECH (Level 0): Pick the minimum key vertex not yet in MST.
        // 💡 THINK: "Which unconnected house is cheapest to connect to our CURRENT grid?"
        int u = minKeyVertex(key, inMST);
        inMST[u] = true;
        
        // 🔧 TECH (Level 0): Update key and parent of neighbors.
        // 💡 THINK: "Now that this house is on the grid, look at its neighbors. Can we connect them cheaper now?"
        for (int v = 0; v < V; v++) {
            // ❓ WHY graph[u][v] < key[v]?: In Dijkstra, we add total distance from start (`dist[u] + graph[u][v]`). In Prim's, we ONLY care about the cost of the single cable (`graph[u][v]`). We don't care how far it is from the start, just how cheap it is to attach to the grid!
            if (graph[u][v] != 0 && !inMST[v] && graph[u][v] < key[v]) {
                parent[v] = u;
                key[v] = graph[u][v];
            }
        }
    }
}



        
Super-Simple Prim's in Python (using Priority Queue)


import heapq

def prims_mst(graph, start):
    # 🔧 TECH (Level 0): Priority Queue stores (weight, node).
    # 💡 THINK: "Sorting hat to instantly find the cheapest available cable."
    pq = [(0, start)]
    visited = set()
    mst_weight = 0
    
    while pq and len(visited) < len(graph):
        # 🔧 TECH (Level 0): Pop the cheapest edge.
        # 💡 THINK: "Grab the cheapest cable we know about."
        weight, node = heapq.heappop(pq)
        
        if node in visited:
            continue
            
        # 🔧 TECH (Level 0): Add to MST.
        # 💡 THINK: "Plug the house into the grid!"
        visited.add(node)
        mst_weight += weight
        
        # 🔧 TECH (Level 0): Add all outbound edges to PQ.
        # 💡 THINK: "Now that this house is online, look at all its outgoing cables and throw them in the sorting hat."
        for neighbor, edge_weight in graph[node].items():
            if neighbor not in visited:
                heapq.heappush(pq, (edge_weight, neighbor))
                
    return mst_weight



        


        
Quick Revision Summary

        
    
            
  • Graph Traversal: Visiting every vertex systematically. Always use a visited array!
    • 
            
  • BFS (Breadth First): Uses a Queue. Level-by-level. Finds shortest paths. O(V+E).
    • 
            
  • DFS (Depth First): Uses a Stack/Recursion. Dives deep. Finds cycles & orders. O(V+E).
    • 
            
  • Multi-source BFS: Put all start locations in the queue at distance 0 before looping.
    • 
            
  • Topological Sort: For DAGs only. Kahn's algorithm (BFS-based) uses In-Degrees and detects cycles naturally.
    • 
            
  • Shortest Path (Weighted): Dijkstra (fast, no negative edges). Bellman-Ford (slower, allows negative edges). Floyd-Warshall (All-Pairs, O(V³)).
    • 
            
  • MST: Kruskal's (Sort Edges + DSU). Prim's (Grow tree + Priority Queue).
    • 
            
  • DSU: Used to track groups and find cycles instantly using path compression.
